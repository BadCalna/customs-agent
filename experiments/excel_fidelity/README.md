# P03 模板映射与插列试验

本目录是离线试验，尚未接入生产上传/导出接口。它验证真实模板能否按表头识别、图片与申报行能否对应，以及在原海关编码右侧新增两列后是否保留原内容。**历史确认值作为原值保留，AI两列留空；不执行商品归类。**

## 当前结论

2026-11-15，用户指定的三份历史最终确认版结构试验通过。三份原件哈希不变；86个申报条目、130条装箱记录可追溯；10,794个原单元格逐格核对；91个媒体资源字节不变。每份输出仅修改申报页、相应绘图位置、工作簿名称/筛选范围三个部件，其余部件字节完全相同。

WPS 与 Microsoft Excel 的实际打开、显示、重算及保存再打开**尚未验收**。本机可发现 WPS 12.1.0.29161 与 Excel 2016，但桌面工具不能激活/还原窗口；不能将结构通过写成双软件兼容通过。WPS `DISPIMG` 在具体 Excel 版本中的显示尤其需要实测。

|---|---|---|---|
| S-P03-01 | 18 / 14 | 装箱页为旧“品名/规格型号”，无别名和独立厂家型号；申报项号在D、要素在AD，无附图表头 | 无可确定的逐商品图片；3个浮图在数据区外，保留为未归属对象 |

S-P03-02有一处倒序范围和一处同合同项不同事实，均列为待核；不改历史项号、不按同名猜关联。表尾发运说明不作为商品；原文与来源行完整保留在原文件和本地报告。按合同项关联只是位置关系，不等于完成P04语义稽核。图片映射不是OCR，也不证明图片内容就是所述商品。

## 如何运行

从仓库根目录运行，Python 3.12+，核心仅使用标准库。可选Pillow用于真正解码图片；未安装时会明确报告`not_run_Pillow_unavailable`，不能视为图片可读已通过。真实试验已使用本机Pillow解码验证。试验不增加公共依赖。

```sh
python -m experiments.excel_fidelity.cli "<本地原始样本.xlsx>" \
  --sample-id S-P03-01 --output-dir data/private/p03/new-run

# 只读映射与资源检查，不生成Excel
python -m experiments.excel_fidelity.cli "<本地原始样本.xlsx>" \
  --sample-id S-P03-01 --output-dir data/private/p03/inspect-run --inspect-only

# 核心试验的独立验证入口
python -m unittest tests.p03.test_fidelity -v

# 已按主工程D6完成环境准备时
make test TASK=P03
# Windows无make时，使用同一Django测试发现入口
python manage.py test tests/p03 --verbosity 2
```

输出目录必须使用新的目录；已有输出及报告不覆盖。核心不原位修改原件。报告包含原始业务值，**放在Git忽略的本地目录，不提交**。

输出：`S-P03-xx-插列验证.xlsx`及`S-P03-xx-report.json`。原HS右侧依次为“AI推荐HScode”“预审结论”；新增内容仅为表头和空白单元格。默认不复制旧HS到AI推荐，也不把旧“OK”写成新审核通过。

报告内容：原件及输出哈希、所有页签/数据边界/字段位置、逐行事实和来源、合同成员关联及歧义、WPS图片ID/媒体/行号/解码状态、浮动对象及未归属对象、差异部件、单元格和元数据核对结果。缺图片、缺资源、坏资源、共享公式缺主公式分别报告；不把读取失败当作无图。

## 方案选择及范围

使用ZIP/XML定点修改，避免整体导入/另存时丢失WPS的`cellimages`、未知扩展、格式或其他页签。只修改已识别的依赖部件；原媒体、共享字符串、样式和其余部件不重建。发布输出前检查ZIP/XML及所有原单元格、公式语义、行设置、合并、列属性、筛选、视图、名称、图片/批注与绘图元数据；不通过则不发布。

支持本批实际观察的普通/共享公式、静态A1跨页签引用、绝对引用、名称/打印范围、合并、筛选范围、视图/冻结、行高/隐藏设置、数据验证和条件格式引用，以及标准浮图锚点、批注与简单VML锚点。对受影响共享公式展开为普通公式，保留其缓存值；未受影响页签的共享公式原样保留。缓存不等于重算证据。

明确拒绝：保护页、已有结果列未明确复用、跨插入边界覆盖结果区的合并、活动筛选条件、表格/透视表/图表/外链/签名宏/计算链、动态INDIRECT/OFFSET/结构化/三维引用、数组/数据表公式、共享资源跨页签、末端列越界及未知目标页扩展等。本试验不是完整Excel编辑器，不承诺未支持特性的保真。样本扩展遇到此类结构应增加适配和验收，不能去掉拒绝规则强行导出。

供P04/P05/P20：`workbook.py`读取包及图片，`mapping.py`提供语义位置和成员候选，`insert.py`提供受限插列试验。先复用数据形状及异常语义，经主控集成后再接生产接口。`tests/p03/fixtures.py`生成完全合成的OOXML结构样例，供自动测试，不是经过Office验收的业务模板。

## 双软件验证和替代路径

逐份使用WPS、Excel打开试验副本，在申报页按Ctrl+Home再检查L～P列表头，抽查首/中/末条图片、原编码、要素、旧意见、汇总公式和其他页签。须记录具体软件版本、修复提示、错误单元格及图片归属；不以“文件可打开”代替全部检查。详细本地清单在`data/private/p03/手工验收清单.md`，不包含在Git中。

若某版本Excel不能显示DISPIMG，保留本格式原件，并评估单独的普通浮图兼容副本或网页图片预览。该替代尚未实现和验收，不能将“图片资源未丢失”等同于Excel已支持。客户端验收未完成前，P20不得承诺双软件保真导出，P04/P05可按已核对的字段及资源映射继续设计。

## 已有结果列的位置差异

用户后续提供了三份另有结果列的模板。按表头语义定位“AI推荐HScode”“业务员确认HScode”“置信度”“预审结论”或“AI预审结论”，兼容英文大小写、空白、括号说明及明确列名别名；不按第一份的列字母写入其他文件。最初三份模板的前三列分别定位为AF/AG/AH、M/N/O、M/N/O，当时均缺独立“预审结论”。后续新增结论及第一份再次调整后的当前结构见下表，历史缺列报告不能作为当前模板的列定位依据。

这些字段加入`declaration.fields`与逐行事实来源；缺列报告，重复语义列拒绝，不以相似内容猜列。尚未实现向已有列写入AI业务结果。两列插入入口只在识别出的表头行检查已有结果列，防止重复插入，并避免历史意见中的同名文字误触发。

用户已确认增加独立“预审结论”。`--add-precheck`为已有模板生成副本，在逻辑数据末尾添加空白结论列，保留原三列位置、原公式和所有其他页签/资源；可分割WPS延伸至XFD的空白列格式，不将尾部格式当作真实数据。新列与既有验证/条件格式冲突时拒绝。输出前逐格和元数据核对通过才发布；已存在结论列或输出文件时拒绝覆盖。结论数据区为空，不冒充AI审查结果。

### 用户最新模板及填充位置

第一份当前结果区依次为AF～AI，原AK“预审结论”表头已移除；装箱明细及其他页签表头未变。以下列字母仅记录本次文件，识别与下游填充必须使用语义字段映射。

| 语义字段 | 第一份当前列名及位置 | 下游填充约定 |
|---|---|---|
| `hs` | L 海关编码 | 供应商原HS，保留用于比较 |
| `elements` | AD 申报要素 | 综合已有资料补充；未知或冲突项说明待补，不臆造 |
| `ai_hs` | AF AI推荐hscode | 写AI独立推荐，不能覆盖供应商原码 |
| `precheck_conclusion` | AG AI预审结论（业务员参考） | 写比较状态、依据、差异/无法确认原因、待补事项及预审等级 |
| `confirmed_hs` | AH 业务员确认Hscode（有变更再填写即可） | 留给业务员，仅有改码时填；AI不自动复制推荐码到此列 |
| `confidence` | AI 置信度（物流审核环节参考） | 写物流/专家审核的高、中、低及依据、待补/修改事项；不与业务员预审结论混列 |

两页签关联：装箱明细合同号B、项号C，对应申报要素采购合同号B、项号D；仍按合同/项号成员关联，不能按行号对齐。装箱品名E、规格型号F与申报品名F综合核对；此份缺独立别名、厂家型号和附图列，应报告缺项，不能把厂商当品牌或型号，不能把表外图片分配给商品。其余两份继续按各自表头识别，结果位置为AI推荐M、预审结论AE、业务员确认N、置信度O。

AH空白只表示没有填写人工改码，不能据此把AF推荐默认为业务员已确认；AF与L有分歧时仍需业务员处理。供应商原要素、原码及历史意见应可追溯。本试验只提供识别和来源映射，实际归类、要素生成及业务结果写回由下游实现；已有四列时不再使用插列/追加列入口。

## PR审查修复与验证

- 有原HS、要素、型号、图片等事实的行即使缺合同/项号/品名也保留，逐行报告缺项；空行、汇总公式、表尾说明分开识别。非数值退税列里的说明文字不单独当作商品。
- 附图列内起止锚点精确落在同一单元格的浮图参与候选行发现；即使没有文字、XML行不存在或仅有样式空格，也保留为待核商品候选并记录图片来源。图片不在附图列、跨行、位于表头或无法定位时继续未归属，不就近猜测。
- 两种结果列导出均补齐图片候选行所需的空白结果格及工作表范围，保留原有行高等属性；单元格和元数据审计覆盖这些新增行。
- 无合同/项号/品名及强商品事实、整行至少两个公式且全部仅汇总本表前序区域时，单独列为`summary_formula_only`。单个数量公式、含额外文字或商品图片的行仍保留待核，不能仅凭缺主键排除。
- 跨页签条件格式、数据验证公式与普通公式一起处理，页签名称按大小写不敏感匹配；不支持的动态或扩展公式在输出前拒绝。审计会检查这些元数据的变换。
- WPS单元格图和普通浮图均执行容器校验与像素加载；损坏图不能报告解码通过，缺少解码能力时待核。表达式/条件DISPIMG只报告候选资源，不推断实际显示，标记人工核对。
- 多条申报行重复关联同一合同项时，所有相关行标记待核并列出冲突申报行号。
- 装箱数量和单位按语义映射，保留零值与原单元格来源，不擅自汇总分箱数据。
- 支持延伸到XFD的统一尾部格式范围；实际末端单元格越界和独立末端样式仍拒绝。

当前独立与Django入口为 **39项测试通过**，包括新版带括号表头、列顺序变化、已有AI预审列保护及同义重复列拒绝。原有三份模板两种导出的6组结构复核是生成时证据，报告在本地`data/private/p03/review-fix-results-20261115-v5/`；用户此后修改的第一份已重新只读核对，三份当前字段映射报告在`data/private/p03/template-check-20261115-v1/`，读取前后哈希不变，未生成新Excel。双软件打开已获用户确认，图片显示、重算和保存重开仍待验收。

## 如何运行

从仓库根目录运行，Python 3.12+，核心仅使用标准库。可选Pillow用于真正解码图片；未安装时会明确报告`not_run_Pillow_unavailable`，不能视为图片可读已通过。真实试验已使用本机Pillow解码验证。试验不增加公共依赖。

```sh
python -m experiments.excel_fidelity.cli "<本地原始样本.xlsx>" \
  --sample-id S-P03-01 --output-dir data/private/p03/new-run

# 只读映射与资源检查，不生成Excel
python -m experiments.excel_fidelity.cli "<本地原始样本.xlsx>" \
  --sample-id S-P03-01 --output-dir data/private/p03/inspect-run --inspect-only

# 已有AI推荐/业务员确认/置信度列的模板，只追加缺失的预审结论列
python -m experiments.excel_fidelity.cli "<已有结果列的模板.xlsx>" \
  --sample-id S-P03-01 --output-dir data/private/p03/conclusion-run --add-precheck

# 核心试验的独立验证入口
python -m unittest tests.p03.test_fidelity tests.p03.test_review_fixes tests.p03.test_compat_images -v

# 单独生成静态普通图片兼容副本，不插列、不修改原WPS文件
python -m experiments.excel_fidelity.cli "<已有附图的模板.xlsx>" \
  --sample-id S-P03-02 --output-dir data/private/p03/excel2016-new-run --excel2016-images

# 已按主工程D6完成环境准备时
make test TASK=P03
# Windows无make时，使用同一Django测试发现入口
python manage.py test tests/p03 --verbosity 2
```

输出目录必须使用新的目录；已有输出及报告不覆盖。核心不原位修改原件。报告包含原始业务值，**放在Git忽略的本地目录，不提交**。

输出：`S-P03-xx-插列验证.xlsx`及`S-P03-xx-report.json`。原HS右侧依次为“AI推荐HScode”“预审结论”；新增内容仅为表头和空白单元格。默认不复制旧HS到AI推荐，也不把旧“OK”写成新审核通过。

报告内容：原件及输出哈希、所有页签/数据边界/字段位置、逐行事实和来源、合同成员关联及歧义、WPS图片ID/媒体/行号/像素解码状态、浮动对象及未归属对象、差异部件、单元格和元数据核对结果。缺图片、缺资源、坏资源、共享公式缺主公式分别报告；不把读取失败当作无图。条件图片候选资源可解码不代表该图片实际显示。

## 方案选择及范围

使用ZIP/XML定点修改，避免整体导入/另存时丢失WPS的`cellimages`、未知扩展、格式或其他页签。只修改已识别的依赖部件；原媒体、共享字符串、样式和其余部件不重建。发布输出前检查ZIP/XML及所有原单元格、公式语义、行设置、合并、列属性、筛选、视图、名称、图片/批注与绘图元数据；不通过则不发布。

支持本批实际观察的普通/共享公式、静态A1跨页签引用、绝对引用、名称/打印范围、合并、筛选范围、视图/冻结、行高/隐藏设置、数据验证和条件格式引用，以及标准浮图锚点、批注与简单VML锚点。对受影响共享公式展开为普通公式，保留其缓存值；未受影响页签的共享公式原样保留。缓存不等于重算证据。

明确拒绝：保护页、已有结果列未明确复用、跨插入边界覆盖结果区的合并、活动筛选条件、表格/透视表/图表/外链/签名宏/计算链、动态INDIRECT/OFFSET/结构化/三维引用、数组/数据表公式、共享资源跨页签、末端列越界及未知目标页扩展等。本试验不是完整Excel编辑器，不承诺未支持特性的保真。样本扩展遇到此类结构应增加适配和验收，不能去掉拒绝规则强行导出。

供P04/P05/P20：`workbook.py`读取包及图片，`mapping.py`提供语义位置和成员候选，`insert.py`提供受限插列试验。先复用数据形状及异常语义，经主控集成后再接生产接口。`tests/p03/fixtures.py`生成完全合成的OOXML结构样例，供自动测试，不是经过Office验收的业务模板。

逐份使用WPS、Excel打开最新试验副本，按本地清单所列位置检查表头，抽查首/中/末条图片、原编码、要素、旧意见、汇总公式和其他页签。须记录具体软件版本、修复提示、错误单元格及图片归属；不以“文件可打开”代替全部检查。详细本地清单在`data/private/p03/验收清单-审查修复版.md`，使用v5副本，不包含在Git中。

Excel 2016原路径失败已由用户实测确认，普通浮图替代现已实现，**兼容副本Microsoft Excel与WPS图片显示均已获用户确认**，重算和保存重开待完成。`compat_images.py`接受商品附图列内可唯一解析、像素解码通过的直接DISPIMG mode 1（包括共享公式从属行），转为标准DrawingML图片，按原单元格行列居中同比例放置。现有浮图、其他单元格及元数据、原媒体保持，图片函数/缓存只在兼容副本中清空并将原公式及来源记入本地报告。图片为静态显示，不再保留DISPIMG动态行为；列宽换算采用近似字体指标并留内边距。

正交旋转/翻转通过派生PNG保留显示方向，原媒体不删除。条件/动态表达式、模式非1、缺失/损坏或未解码资源、隐藏或合并的图片格、裁剪/复杂效果、宏/签名/计算链及共享绘图等明确拒绝，不猜图。仅向新文件发布，审计失败或源文件途中变化不发布；本模式不插列、追加结论或填写业务结果。

## 后续落库建议

1. **原始快照**：先登记文件哈希、批次、来源类型、文件内采集时间、官方来源 URL、原页签和行号，再导入暂存层；使用哈希避免相同文件重复导入。
2. **HS 与要素关系**：十位 HS、计量单位代码、监管条件代码和适用前缀按文本保存，保留前导零和原文。适用前缀按原表保存，不统一裁成前四位。HS目录、要素定义和映射关系分别管理，关联到原始快照。
3. **必填与顺序**：必填标记保留 1/0。明细没有官方申报排列顺序字段，文件行序仅是来源定位，不当作官方申报顺序；正式拼接前需补证据并确认顺序。
4. **历史案例**：按“文件哈希＋申报页签＋源行”定位案例，装箱资料用于关联商品事实；保留原 HS、原申报要素、规格/型号、图片和原位置。成功案例仅用于相似案例参考，不能替代当前官方规则或自动判定新商品高置信度。
5. **日期和版本**：本批未确认规则生效/失效日期及适用进出口范围，不将归档日补为生效日。后续年度更新先落新快照，再比较新增、删除、名称、要素和必填标记变化；保留旧版本及差异，不覆盖历史审核依据。
6. **待核记录**：未匹配、冲突及来源缺口单独标记；保留原值，不能靠空白补零、猜编码或改品名来消除问题。监管条件代码本身也不等同于完整军民两用管制判断。

本批原件含合同与供应商业务资料，仓库访问范围应与资料使用范围一致。数据库导入、数据权限和专业质量验收由后续任务分别实现。

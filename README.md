# AI 智能关务 · Customs Agent

用于开发辅助关务工作的 AI Agent 应用，帮助关务人员处理资料、查询知识和梳理业务流程。

## 工作台前端（定稿 UI · 独立演示入口）

定稿的三角色工作台以**独立演示入口**接入：`/workbench/`，或 `make workbench` 启动。**默认 FIXTURE 样例数据，现有首页保持不变**；真实数据读取与审批接口接通后，再将其设为首页。

- 数据三模：默认 **FIXTURE**（`contracts/fixtures/DEMO-SET.json`）；`?mode=live` 读 `/api/v1`（Django Ninja）；`?mode=demo` 用内置演示数据。顶栏芯片标明当前数据源。
- 读路径已按契约映射（任务/版本/商品/依据/附图/六类比较结论）；写动作后端仍为 501，前端做乐观本地演示并如实标注，待后端 P 任务落地后接通。
- 提交闸门：只要还有商品未确认，显示"还有 N 条待确认"并**禁用整批提交**；全部确认后才可提交专家。
- 设计源文件保留在 `docs/原型/关务审核工作台-v2.html`；项目运行版为 `web/workbench.html`。

## 计划探索的方向

- 关务知识与政策查询，提供可追溯的来源。
- 单证信息提取、整理与一致性检查。
- 报关要素辅助整理与业务风险提示。
- 通过工具调用协助完成重复性关务工作。

## 开发约定

- API 密钥等配置通过环境变量管理，需要配置模板时使用 `.env.example`。
- 本地业务资料放在 `data/private/`、`uploads/` 或 `docs/参考模板/`，这些目录已被 Git 忽略。
- 业务对象统一称“审核任务”；技术设计中的“导入批次”（import_batches）只是文件版本的技术载体，归属审核任务。
- Agent 的业务建议应保留依据，关键关务结论由业务人员复核。

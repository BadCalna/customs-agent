# AI 智能关务 · Customs Agent

用于开发辅助关务工作的 AI Agent 应用，帮助关务人员处理资料、查询知识和梳理业务流程。

## 正式工作台

访问 `/workbench/`，或 `make workbench` 启动，默认使用真实登录会话与 `/api/v1`。上传和认领仍走 `/uploads/`，两页共享会话。任务按服务端范围、阶段和游标分页；选择明确的版本、阶段与执行记录后查看 P07 卡片、P08 进度及 P20 导出。

- 登录、权限或网络错误直接显示，不回退样例。两类导出直接返回 XLSX，绑定所选版本和 Run；专家清单还绑定对应提交及可选决定。
- AI 当前仍为 mock / inline。P13 队列、重试授权及专家工作簿列布局未发布，对应入口禁用并说明。
- 正式静态资源在 `/workbench/assets/` 白名单，支持 `DEBUG=False`；API 继续校验会话、CSRF 和任务权限。未部署或浏览器验收通过。
- 原交互原型保留在 `web/workbench.html`，仅在开发模式显式 `?mode=fixture` / `?mode=demo` 访问。设计源文件仍在 `docs/原型/关务审核工作台-v2.html`。
- 验证结果与浏览器阻塞详见 [P08/P20 集成记录](docs/开发文档/验收记录/P08-P20-正式页面集成-20261117.md)。

## 计划探索的方向

- 关务知识与政策查询，提供可追溯的来源。
- 单证信息提取、整理与一致性检查。
- 报关要素辅助整理与业务风险提示。
- 通过工具调用协助完成重复性关务工作。

## 开发约定

- API 密钥等配置通过环境变量管理，需要配置模板时使用 `.env.example`。
- 本地业务资料放在 `data/private/`、`uploads/` 或 `docs/参考模板/`，这些目录已被 Git 忽略。
- 业务对象统一称“审核任务”；技术设计中的“导入批次”（import_batches）只是文件版本的技术载体，归属审核任务。
- Agent 的业务建议应保留依据，关键关务结论由业务人员复核。

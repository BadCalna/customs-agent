# AI 辅助申报要素与 HS 归类 · 数据源清单

> 版本：v0.1（2026-11-04）
> 用途：明确系统需要哪些数据、从哪拿、用在哪一层、谁来负责。
> 优先级：P0 = 10 天演示版必需；P1 = 试点期（6–8 周）必需；P2 = 长期完善。
> 难度：★ 容易获取 / ★★ 需要整理或抓取 / ★★★ 需要跨部门推动或长期积累。

|---|---|---|---|---|---|

## 六、所有入库数据必须带的元数据

无论哪一类，入库时统一携带以下字段，否则后期无法追溯与版本管理：

| 字段 | 说明 |
|---|---|
| `source_type` | official_tariff / official_declaration / enterprise_history / third_party / manual_rule |
| `source_ref` | 来源 URL、公告号、单号或文件路径 |
| `effective_date` / `expire_date` | 生效与失效日期，支撑转版与老码拦截 |
| `tariff_version` | 税则年度版本，如 2026 |
| `confidence_tier` | authoritative / verified_history / unverified_third_party |
| `review_status` | 是否经关务人员复核、复核人、复核时间 |

## 七、风险与边界

1. **官方无开放 API**：税则与申报要素需页面整理 + 人工兜底，首次全量导入与年度更新要明确责任人。
2. **历史数据有毒**：存量错码会被 RAG 固化成"标准答案"，入库前必须过一遍改单/退单记录做负向标注。
3. **退税与海关口径分离**：退税率来自税务体系，不能与海关税则混库管理。
4. **企业数据不出域**：历史申报、供应商、价格信息属敏感数据，调用外部模型前需脱敏（去供应商名、去金额、去客户）。
5. **第三方库仅初筛**：任何第三方编码结论必须回官方当期数据核验后才可进入高置信档。

| 6 | 出口退税率文库 | `adapters/sources/tax_lookup.py` | `CUSTOMS_TAX_RATE_PATH` | 总局门户可达但无公开文库文件/接口；未取得文库，退税率一律标待核 |

配套口径：

- **退税与海关税则分库**：退税率文件与 `CUSTOMS_TARIFF_PATH` 必须是两个文件，不能混库（对应第 7 节第 3 条）；
- **不内置代码含义表**：监管证件代码的名称与主管机关只能来自导入数据；只有代码时标
  `REG_MEASURE_NAME_UNKNOWN` 并转专家，不由模型或硬编码补（对应第 7 节第 5 条“第三方库仅初筛”的同一条底线）；
- **条件与两用物项不自动判定**：政策条件文本未机读化前一律待核；两用物项只输出清单线索，
  必须由专家按技术参数、最终用途与用户判定；
- 文件格式、导入与复核步骤见 D6 第 2.6 节；分项输出与 P18 集成规则见 D4 第 7 节。

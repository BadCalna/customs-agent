## 一、业务流程现状（11步）

```
ERP拟签 → 采购合同签订 → 货物申报要素制作 → 物流文员审核 → 货物到货
→ 报关单据制作 → 报关预录单核对 → 完成报关 → 大副收据核对
→ 提单草本核对 → 确认提单正本
```

各环节关键点（人工核对重点）：

| 环节 | 关键字段 |
|---|---|
| 货物申报要素制作 | HS编码是否正确、申报要素是否完整且合理 |
| 报关单据制作 | 重量、件数、品名 |
| 报关预录单核对 | 重量、件数、品名、境内货源地 |
| 大副收据核对 | 重量、件数、品名 |
| 提单草本核对 | 重量、件数、品名、船名、航次 |

## 二、业务痛点（会议共识）

1. **最大痛点：申报要素与HS归类的"准确性瓶颈"**——上游乱填（供应商填写不准、配合度低）、中游没能力核（业务员缺乏归类专业能力与动力，如焊丝/焊条退税差异）、下游没时间核（货到后申报，工作堆积在最后两周，物流单人判断、风险集中末端）。
2. **结构性痛点：货到后申报 → 时间极度压缩**，全员高强度加班。
3. 申报要素识别错误会引发外部合规风险（海关质疑、退税损失、扣货退运）。

## 三、AI全流程重构方案（项目定位：全流程重构，非单点赋能）

**三条重构主线：**
1. 申报准备前移——合同阶段即生成申报任务、按到港时间倒排提醒，到货前完成要素制作与审核；
2. 核对能力产品化——重量/件数/品名等关键点全部AI自动比对，人工只处理标红异常；
3. 知识库贯穿——每次审核通过的申报自动回流沉淀，AI推荐优先命中历史记录。

**双端载体：**
- 业务员端：钉钉H5微应用（品名+规格+图片录入 → AI推荐HS编码与申报要素 → 缺失字段补数清单可转发供应商）；
- 物流/审核端：网页工作台（申报单AI预审、Excel批量导入异常标注、单证比对差异报告、知识库管理）。

**AI推荐可信度分级规则（核心业务规则）：**
- 高置信度：命中企业历史申报成功记录或官方税则精确匹配 → 直接确认提交；
- 中置信度：仅第三方数据源匹配 → 标注"待官方核验"，物流端复核；
- 低置信度：多候选得分接近或关键归类字段（电压/材质/成分）缺失 → 不给唯一推荐，生成补数清单；疑难项提示申请海关预裁定（署令236号）。

**单证核对基准（跨页规则）：**

| 核对环节 | 基准单据 | 关键字段 |
|---|---|---|
| 报关单据制作 | 合同+发票+装箱单（三单交叉校验） | 重量、件数、品名 |
| 预录单核对 | 报关单据 | 重量、件数、品名、境内货源地 |
| 大副收据核对 | 报关单据+装箱单 | 重量、件数、品名 |
| 提单草本核对 | 大副收据+报关单据+订舱信息 | 重量、件数、品名、船名、航次 |

## 四、HS编码数据源策略（不采购，自建知识库）

- **官方公开渠道**：海关总署「互联网+海关」进出口税则查询（customs.gov.cn → 政务服务 → 我要查）、中国国际贸易单一窗口（singlewindow.cn → 参数查询）、海关总署公告栏目（增量更新来源）、「海关归类一指通」微信公众号、12360热线；
- **官方无开放API**，只能页面抓取+人工兜底；税则每年集中调整一次，更新负担可控（年度全量 + 公告增量）；
- **申报要素清单最难拿**：官方不提供批量下载——所以企业历史申报记录是最独特资产；
- 第三方HS编码库（hsguilei.com、i5a6.com、hsbianma.com 等）数据整理自海关公开数据，**仅作初筛层，不可作为合规依据**，须以官方当期数据核验；
- 架构：企业历史申报数据（RAG主力）+ 官方税则数据 + 海关公告解读 + 预裁定/归类决定判例库。

## 五、已验证归类案例库（兼作AI提示词回归测试集）

| 商品 | 归类结论 | 关键经验 |
|---|---|---|
| 深沟球轴承 6224/C3（SKF） | **8482102000**，退税13%，监管条件无 | 型号即规格，C3游隙属型号组成部分；"结构类型"可由型号规则库推断；要素示例 `4\|1\|深沟球轴承\|减少摩擦，滚动支撑用\|SKF\|6224/C3\|无\|无` |
| 热过载继电器 LRD12C/5.5-8A（施耐德） | **85364900.90**（>60V，旧码85364900.00已作废拆分），监管条件A | 继电器归类第一依据是**电压**（≤36V / 36-60V / >60V 三档），品名规格看不出，需读铭牌/规格书 |
| 固态继电器 125A（"固体继电器"为错别字） | 推荐 85364900.90（中置信），**缺电压/品牌/型号无法定码** | "电柜"是用途不是品类；125A是电流不是型号；典型"信息不足"案例——AI应输出缺失字段补数清单而非硬猜 |

**规律总结**：标准化工业品（轴承）型号承载结构信息，AI易做；俗名商品（焊丝/焊条）与参数依赖商品（继电器按电压分档）才是AI价值最大的场景，需要"品名+规格+图片"三合一输入。

## 六、实现决策与排期

- 范围：**10天AI辅助开发版**，只做"申报要素与HS归类辅助"一条主线（业务员录入→AI推荐→提交→文员审核→通过入库），砍掉：Excel批量导入、单证OCR比对、转发供应商、倒排提醒、统计看板（二期增量）；
- 技术栈建议：Python FastAPI + SQLite/MySQL + 原型HTML改造；
- 关键风险：①提示词质量决定成色——用第五节三个案例做回归测试集，每次改提示词跑一遍；②铭牌图片OCR识别效果提前测，识别不准就让用户手填；
- 钉钉发布路径：企业内部H5微应用（开放平台建应用配首页URL），需要钉钉管理员开通权限；最简起步可先网页链接+账号密码登录，免登后补；
- 协作：仓库邀请Collaborators即可，与token无关。

# 专家核查调试模块实施计划

目标：在既有 Agent 调试台中独立调试 P18 专家核查，展示要素、图片、退税、监管四项结果和对应执行记录。

基线：远程 main `44bf1257238658eb75ff6fb2f55fb441969a0525`。实现位于隔离本地目录；发布 PR 时以该真实上游提交为父提交，仅包含本模块变更，不携带本地快照仓库历史。

架构：保留预审默认入口；新增 `stage=expert_check` 与严格专家输入。阶段及输入冻结在加密预览和运行快照内。现有单次 HTTP transport、权限、额度、过期控制、摘要确认和证据映射继续使用。专家适配器显式注入同一发布版本的 P14/P17 来源；无图、无监管依据均保持 unknown。模型仅在 P18 原有前提成立时调用，来源核对不需要模型时记录零次出站。

1. 新增专家输入和阶段契约，保持已有预审请求、样例和审批摘要兼容；复制运行保持原阶段及输入，禁止覆盖固定样例。
2. 封装已有 ExpertCheckEngine，预览捕获实际模型请求、冻结来源；核查结果使用固定安全文案，原模型自由文本不进入摘要。
3. worker 按阶段执行，记录模型/解析/来源核对步骤，正确区分技术失败与业务待核。所有结果仅写 DebugRun，不写正式任务或审核决定。
4. 扩展现有表单、运行列表与详情：待核查 HS、退税率、方向、版本/日期及四项核查结果，证据依旧使用同源精确映射；第一版不接图片上传。
5. 验证预审兼容性、专家 mock/live/source-only、坏 JSON、来源失败、模型超时、重跑/幂等/快照绑定、权限与脱敏；执行现有调试套件和 P18 回归，检查 Django 与迁移漂移。

交付：隔离开发目录、可直接应用到基线的补丁、验证记录、模块安装说明补充。真实业务模型质量不以合成/假 provider 测试代替。

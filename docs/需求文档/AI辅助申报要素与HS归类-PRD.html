一、需求背景

公司进口业务沿用"货到后申报"模式，报关全流程共11步：ERP拟签→采购合同签订→货物申报要素制作→物流文员审核→货物到货→报关单据制作→报关预录单核对→完成报关→大副收据核对→提单草本核对→确认提单正本。其中申报要素制作环节依赖业务员填写品名、规格、HS编码和申报要素，物流文员人工审核。业务员对产品归类缺乏专业能力（如焊丝与焊条因成分、形态差异对应不同税则号列和退税率，仅凭俗名无法判断），也缺乏填写动力；供应商填写不准、配合度低，错误从源头进入流程；物流专员单人判断、末端审核无力把关。

由此造成三重影响：其一，归类错误直接导致退税损失、海关质疑与合规风险，且风险全部集中在物流环节末端；其二，所有单证工作堆积在货到后的最后两周，全员高强度加班，单证在"报关单据→预录单→大副收据→提单草本"间反复人工核对同一组数据（重量、件数、品名）；其三，人工逐项核对效率低、易漏检，申报要素若识别错误还可能引发外部风险。典型例证：固态继电器125A这类商品，供应商仅提供"品名+电流"，缺少电压、品牌、型号三项关键信息，按现行流程要到审核端甚至报关端才能发现，返工成本高。

证据说明：暂无量化基线数据（单票要素制作耗时、归类差错率、审核退回率、加班人天均未统计），本判断基于业务方会议共识与三个商品验证案例（轴承6224/C3、热过载继电器LRD12C、固态继电器125A）的实查结果；量化基线待上线后补测。

二、需求目标

让业务员"填得省事、填得正确"，让物流端"只看异常、不再全量核对"，把申报准备工作从货到后两周前移到合同阶段，并通过知识库沉淀让归类准确率持续提升。

三、需求概述（功能清单）

本期范围
  • 业务员端（钉钉H5微应用）：申报任务承接（源自合同/采购单）、品名+规格+图片录入、AI推荐HS编码与申报要素清单、缺失字段补数引导、提交送审
  • 物流审核端（网页工作台）：申报单AI预审与异常标注、批量Excel导入与异常行识别、人工复核与放行/退回
  • 单证智能核对（工作台）：报关单据制作辅助、报关预录单/大副收据/提单草本的自动比对与差异报告、船名航次等关键字段核验
  • 知识库与数据管理（工作台）：企业历史申报记录沉淀、官方税则数据查看与更新机制、待官方核验事项管理
  • 全流程重构：申报准备前移至合同阶段（到货前完成要素制作与审核），关键核对点全部AI自动比对
本期不做什么 / 暂不展开
  • 不做ERP拟签与采购合同签订环节的改造——ERP与合同系统由IT统一规划，本期仅在合同/采购单生成后承接任务，不改动其流程（依赖系统对接排期）
  • 不做报关申报与海关系统直连——报关发送仍走现有报关行/单一窗口通道，本期只做"预录单核对"前的比对
  • 不做商业HS数据库采购——知识库坚持"官方公开数据+企业历史申报记录"自建路线；第三方免费数据仅作AI推荐初筛层且标注来源
  • 不做供应商端入口——供应商信息补全通过业务员转发"补数清单"完成，供应商直接使用的入口留待后续版本
  • 暂不展开移动端审核——物流审核与单证核对均为PC工作台场景，不做移动端适配
模块一级功能说明
1 业务员端·钉钉H5申报任务列表承接合同/采购单生成的申报任务，按到港时间倒排提醒，驱动要素准备前移
1 业务员端·钉钉H5要素录入与AI推荐品名+规格+图片（铭牌/实物照）录入，AI返回HS编码候选（含置信度）、申报要素清单与填写建议
1 业务员端·钉钉H5缺失字段补数信息不足时（如缺电压/品牌/型号），生成待补清单并引导补充，而非事后退回
2 物流审核端·工作台申报单审核AI预审标注异常行（归类存疑/要素缺失/与历史申报不一致），文员只复核标红项后放行或退回
2 物流审核端·工作台Excel批量导入与异常识别批量导入申报明细，AI逐行校验并标注异常，导出带标注结果
3 单证智能核对·工作台报关单据制作辅助从合同/发票/装箱单提取重量、件数、品名，自动填充并多源交叉校验
3 单证智能核对·工作台预录单/收据/提单核对预录单、大副收据、提单草本与基准单据逐字段自动比对，生成差异报告；提单核对含船名、航次
4 知识库·工作台历史申报记录沉淀审核通过的申报自动入库，形成"品名+规格→编码+要素"检索资产，AI优先命中
4 知识库·工作台税则数据管理与核验官方税则数据查看、更新任务提醒、待官方核验事项（第三方初筛结果）集中处理

3.1 AI推荐结果可信度分级规则（跨页共享）

等级判定条件处理方式
高置信度命中企业历史申报成功记录，或官方税则数据精确匹配直接展示推荐结果，业务员确认即可提交
中置信度仅第三方数据源匹配，或历史记录命中但规格有差异展示推荐结果并标注"待官方核验"，提示提交后由物流端复核
低置信度多候选编码得分接近、或关键归类依据字段（如电压、材质、成分）缺失不给唯一推荐，列出候选及判断依据，并生成缺失字段补数清单；疑难项提示可申请海关预裁定

3.2 单证核对基准与关键字段规则（跨页共享）

核对环节基准单据关键字段
报关单据制作合同 + 发票 + 装箱单重量、件数、品名（三单交叉校验）
报关预录单核对报关单据重量、件数、品名、境内货源地
大副收据核对报关单据 + 装箱单重量、件数、品名
提单草本核对大副收据 + 报关单据 + 订舱信息重量、件数、品名、船名、航次

1
业务员端
钉钉H5		 1.1 申报任务列表
【页面元素】

1、顶部标题栏：文案"申报任务"，右侧刷新图标

2、任务卡片：每张卡片含商品名称、供应商、合同号、预计到港日期、要素准备截止日、状态标签（待填报/待补数/已提交/已通过/已退回）

3、倒排提醒条：黄色横幅，文案"距要素准备截止还有N天"

4、底部说明：文案"任务由采购合同生成，请在到港前完成要素填写并通过审核"

【交互说明】

1、点击任务卡片 → 进入该任务的要素录入页

2、点击刷新图标 → 重新拉取任务列表

【功能逻辑】

1、任务按要素准备截止日升序排列，已逾期任务置顶并标红

2、状态标签"已退回"的卡片显示退回原因摘要，点击可直接进入修改

【边界说明】

1、无任务 → 展示空态插画与文案"暂无申报任务"

2、网络异常 → 展示重试按钮，文案"加载失败，点击重试"
1.2 要素录入
【页面元素】

1、顶部标题栏：文案"要素录入"，左侧返回按钮

2、商品信息区：品名输入框、规格型号输入框、品牌输入框（可留空）

3、图片上传区：文案"上传铭牌或实物照片"，支持拍照/相册，最多3张，缩略图预览

4、AI识别按钮：文案"AI识别并推荐"

5、参考信息折叠区：合同中的商品描述、供应商、数量

【交互说明】

1、点击"AI识别并推荐" → 按钮变为"识别中…"，完成后跳转AI推荐结果页

2、点击图片缩略图 → 全屏预览，支持删除重传

3、点击参考信息折叠区 → 展开/收起合同参考信息

【功能逻辑】

1、品名+规格+图片三项至少填品名与规格之一方可触发AI识别；仅填品名时提示结果置信度可能较低

2、AI识别自动纠正常见品名错别字（如"固体继电器"归一为"固态继电器"），纠错结果回显在输入框并标注"已自动更正"

【边界说明】

1、AI识别超时（超过30秒）→ 弹窗提示"识别超时，请重试或补充更多信息"

2、图片模糊或无法解析 → 在结果页提示"图片未能识别，建议补拍铭牌特写"
1.3 AI推荐结果
【页面元素】

1、推荐编码卡片：HS编码、商品名称、置信度标签（高/中/低）、数据来源标签（历史申报/官方税则/第三方初筛）

2、候选编码列表：其余候选编码及推荐理由（如"按工作电压>60V归类"），可展开

3、申报要素清单：逐项要素名称与填写值（如"用途：用于电柜电路通断控制"），可逐项编辑

4、税率信息条：出口退税率、监管条件摘要

5、底部操作：按钮"确认提交审核"、"换一个候选"

【交互说明】

1、点击要素项 → 行内编辑填写值

2、点击"换一个候选" → 展开候选编码列表供选择，选择后要素清单与税率信息联动刷新

3、点击"确认提交审核" → 提交并返回任务列表，卡片状态变为"已提交"

【功能逻辑】

1、推荐结果按3.1规则分级：高置信度直接展示；中置信度在卡片标注"待官方核验"；低置信度不给唯一推荐并引导进入1.4补数页

2、要素清单按选定编码的官方申报要求生成必填项，GTIN/CAS无值时默认填"无"

【边界说明】

1、候选编码得分接近（低置信度）→ 不展示"确认提交"按钮，展示"补充信息"按钮进入1.4

2、识别到敏感/管制商品特征 → 红色警示条"该商品可能涉及监管条件，提交后将由物流端重点复核"
1.4 缺失字段补数
【页面元素】

1、顶部说明条：文案"以下信息影响归类判断，请补充后重新识别"

2、待补字段列表：字段名、缺失原因（如"电压决定编码三档划分"）、输入框或拍照上传入口

3、转发按钮：文案"发给供应商补数"（生成待补清单卡片转发钉钉会话）

4、重新识别按钮：文案"已补充，重新识别"

【交互说明】

1、逐项填写或上传 → 字段状态从"待补"变为"已补"

2、点击"发给供应商补数" → 唤起钉钉会话选择器，发送含字段清单的卡片消息

3、点击"已补充，重新识别" → 返回1.3重新获取推荐结果

【功能逻辑】

1、待补清单仅列出影响归类判定的字段（按编码规则库推导），不做全量字段轰炸

2、供应商回复的信息由业务员代填入库，不做供应商自动回传

【边界说明】

1、业务员选择"暂无法补充" → 任务保留"待补数"状态并按天提醒，不阻塞其他任务

2、长期（超过要素准备截止日）未补 → 任务升级提醒推送至物流专员

2.3 Excel批量导入与异常识别
【页面元素】

1、上传区：拖拽或点击上传Excel，模板下载链接

2、识别进度条：文案"正在识别第N/M行…"

3、结果表格：逐行展示导入数据 + AI标注列（正常/异常+异常原因，如"缺电压""编码与品名不符""与历史申报不一致"），异常行红色高亮

4、操作栏：按钮"导出带标注结果"、"仅导出异常行"、"全部重新识别"

【交互说明】

1、点击异常原因 → 弹出该行AI判定详情与建议修正值

2、点击"导出带标注结果" → 下载Excel，异常标注以批注/颜色保留

3、修正行内数据后 → 该行出现"重新识别"按钮，单独重跑

【功能逻辑】

1、识别顺序：先品名归一纠错，再按3.1规则做编码与要素校验，最后比对历史申报记录

2、异常分类固定四类：归类存疑、要素缺失、品名不规范、与历史申报不一致

【边界说明】

1、文件格式不符/超过行数上限（1000行）→ 上传即拦截并提示

2、某行识别失败 → 该行标注"识别失败"，不影响其余行

3.2 单证比对与差异报告
【页面元素】

【页面元素】

1、Tab页：历史申报记录 / 税则数据 / 待官方核验

2、在待核验清单登记核验结果 → 该条状态变为"已核验"，并同步修正对应推荐数据

3、点击年度更新横幅 → 进入更新任务说明页（列出更新步骤与责任人）

【功能逻辑】

【边界说明】

1、税则年度切换后，历史记录中已停用编码标注"编码已停用，请重新归类"，不再参与高置信度命中

2、待核验条目超过30天未处理 → 升级提醒推送至物流专员

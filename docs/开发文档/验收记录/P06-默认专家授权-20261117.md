# P06 / PR #22 默认专家授权修复（2026-11-17）

## 问题与原因

新 Excel 上传、业务员认领并确认后，提交接口只创建 pending 快照与专家 AI 执行，没有建立专家 TaskAssignment。专家读任务因此 404；既有测试事先预授权专家，遗漏真实新任务交接。

## 修复行为

- 任务已经有活跃且角色正确的专家时，保留现有授权，不额外扩大可见人群。
- 否则按服务端 `CUSTOMS_DEFAULT_EXPERT_USERNAME` 选择已有、启用、角色为 expert 的账号，在提交同一事务中创建该任务授权。开发默认 `expert`；真实试用设置为实际账号，不创建账号、不修改密码。
- 默认账号为空、不存在、停用或角色不符时返回 409 `default_expert_unavailable`；授权角色冲突返回 409 `expert_assignment_conflict`。提交、阶段、授权和审计整体回滚，不新留无人能审的 pending。
- 创建授权留 `task.expert_assigned` 审计，绑定提交和来源。重复请求不新增授权、提交或执行。
- 同幂等请求或同内容当前 pending 重放可补旧任务漏授权；已经结束的提交和旧版提交重放不重新授予已移除权限。
- 未修改角色动作矩阵。其他未授权专家、供应商和业务员仍按原对象权限处理。

## 已有 pending 任务修复

在目标环境设置正确的默认专家，并重启应用。对明确的当前任务先预览：

```text
python manage.py repair_pending_expert <task_id>
python manage.py repair_pending_expert <task_id> --apply
```

默认预览不写入；实际执行只给当前版本 pending 提交补授权并追加审计，不修改提交快照、阶段、编码或决定。再次执行不重复。无当前待审提交时拒绝，不提供自动全库放权。

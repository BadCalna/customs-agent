# S01–S12 人工签收表（按 A01–A12）

版本：1.0，2026-11-17。本文把 D5 中的 A01–A12 映射为便于业务人员执行的 S01–S12。它是人工走查表，不替代自动化测试，也不把 mock 结果当作真实报关结论。

## 使用规则

每个场景都要记录：

- 测试人、角色、日期、环境和代码分支；
- 输入文件名、文件版本、任务 ID、商品行/源单元格；
- 预期结果和实际结果；
- 截图或接口结果作为证据；
- 结论：通过 / 不通过 / 阻塞；
- 不通过时记录问题编号、复现步骤和责任人。

原始业务文件只读使用。需要修改、删行或故意制造异常时，先复制到测试目录并改名，不能修改历史成功案例。

## S01：原码与独立建议一致、证据充分（A01）

**目的：** 验证系统能给出一致建议，但仍必须经过业务员确认和专家人工决定。

**操作：**

1. 供应商上传资料齐全的 Excel。
2. 等待自动预审完成。
3. 打开商品行，记录供应商 HS、AI 推荐 HS、置信度、依据和证据。
4. 业务员确认 HS，提交审核。
5. 专家打开提交快照，核对申报要素、图片和 HS。
6. 专家执行通过。

**通过标准：**

- AI 建议和供应商原码分别保存；
- 一致不等于自动通过；
- 业务员提交值被固定为专家审核输入；
- 专家通过人、时间、决定和最终值可追溯。

**证据：** 预审结果截图、提交编号、专家决定编号、历史记录截图。

## S02：同码但缺关键证据（A02）

**目的：** 验证编码表面一致时，资料不足仍不能自动确认。

**操作：**

1. 使用缺材质、用途、成分、型号或图片的商品行。
2. 等待预审完成。
3. 查看 HS 是否一致，但证据状态是否为缺失/待核。
4. 查看问题清单和待补充信息。

**通过标准：**

- 原 HS 和 AI 建议仍分别展示；
- 置信度不能因为编码一致就自动变成高；
- 具体缺失字段、来源位置和补充责任人明确；
- 业务员仍需人工确认，不能直接视为报关可用。

**证据：** 商品卡片截图、问题清单、预审结论。

## S03：原码与建议不一致（A03）

**目的：** 验证系统能清楚区分供应商原码、AI 建议和实际提交值。

**操作：**

1. 上传供应商 HS 与预期 AI 建议不同的样本。
2. 查看预审结论和差异原因。
3. 业务员选择确认值并提交。
4. 专家核对原码、推荐码和提交码。

**通过标准：**

- 不覆盖供应商原 HS；
- 差异原因、证据和置信度可见；
- 实际提交值单独保存；
- AI 不直接修改审批状态。

## S04：供应商未填写 HS（A04）

**目的：** 验证原 HS 为空时，系统可以独立给出建议或明确待补资料。

**操作：**

1. 使用供应商 HS 为空的行。
2. 执行预审。
3. 查看原 HS、AI 推荐 HS、置信度和问题。

**通过标准：**

- 原 HS 保持为空；
- 推荐值不能回填到供应商原值列；
- 信息充分时可给候选推荐；
- 信息不足时说明需要补充什么，不能编造编码。

## S05：编码格式异常或适用版本待核（A05）

**目的：** 区分“格式错误”“查询无结果”“版本/日期无法确认”。

**操作：**

1. 分别测试全角数字、位数错误、含字母、旧版本编码或缺少适用日期。
2. 查看系统提示和来源状态。

**通过标准：**

- 格式问题、有效性问题和版本未知分别说明；
- 查询失败不能直接写成“编码无效”；
- 没有适用日期时不能用查询日期冒充申报日期；
- 需要专家处理的项目被明确标出。

## S06：缺页签、重复项或关联歧义（A06）

**目的：** 验证模板结构和装箱关联错误可定位，系统不任意选行。

**操作：**

1. 复制测试 Excel。
2. 分别制造缺少页签、重复必需列、缺合同号、重复项号或装箱项号无法唯一关联。
3. 上传并查看解析报告。

**通过标准：**

- 明确显示工作表、行号、列号和错误原因；
- 阻断错误不产生虚假的成功预审；
- 不静默丢行、不任意关联、不任选一个重复项；
- 原件和失败记录仍可回查。

## S07：图片缺失、损坏或错归属（A07）

**目的：** 区分无图片、图片读取失败和图片归属错误。

**操作：**

1. 使用无图片的行、图片资源损坏的行、图片错放到其他商品的副本。
2. 上传并查看商品图片状态。
3. 检查商品卡片的图片来源单元格和错误信息。

**通过标准：**

- absent、read_failed、错归属分别显示；
- 读取失败不能标成“无图片”；
- 错误图片不能进入另一商品；
- 图片异常时商品行仍保留并转人工核对。

## S08：查询失败或没有适用依据（A08）

**目的：** 验证查询不到官方/第三方依据时不编造证据，也不虚报高置信度。

**操作：**

1. 使用查询不到 HS、申报要素、退税率或监管条件的样本。
2. 查看来源状态、证据列表和待处理原因。

**通过标准：**

- 查询失败、无结果、来源未配置状态分开；
- 不生成虚假公告号、条款号或链接；
- 置信度不能无依据评高；
- 明确转供应商、业务员或专家处理。

## S09：单行模型失败（A09）

**目的：** 验证单行技术失败不阻断其他行，并且有有限重试和尝试记录。

**操作：**

1. 打开固定 P13 任务：[失败行重试任务](http://127.0.0.1:8033/uploads/?task=6a7e92c4-7269-41fd-a313-25a1e239bdfc)。
2. 登录 `operator_a`。
3. 确认初始状态是 3 行中 2 行成功、1 行失败。
4. 勾选失败行，点击“重试所选失败行”。
5. 等待新轮完成。

**通过标准：**

- 失败行最多自动尝试 3 次；
- 其他行结果保留，不被失败行拖失败；
- 新轮只重试选中的失败行；
- 旧轮、旧尝试记录和错误原因仍可查看；
- 新轮完成后进度正确更新。

## S10：导出补料清单（A10）

**目的：** 验证导出只生成补料资料，不自动改变审批状态。

**操作：**

1. 打开包含待补信息的任务。
2. 选择导出补料清单。
3. 打开导出的文件，核对商品、问题、原位置、需补充信息和建议处理人。
4. 回到任务页面查看状态。

**通过标准：**

- 导出内容可以定位到具体商品和来源位置；
- 不自动退回、不自动发送供应商；
- 导出前后任务状态、版本和审批记录不变；
- 文件在 Microsoft Excel/WPS 中可打开。

**当前状态：** 若当前分支没有正式导出入口，记录“待 P20 页面集成”，不要用手工复制 Excel 代替签收。

## S11：专家分别退回业务员/供应商（A11）

**目的：** 验证不同退回对象、责任人和处理路径可追溯。

**操作：**

1. 专家打开待审核提交。
2. 场景一：退回业务员，填写商品、问题、原因和责任人。
3. 场景二：退回供应商补充资料，填写缺失字段、商品和责任人。
4. 检查任务阶段、问题记录、审计记录和后续入口。

**通过标准：**

- 业务员退回和供应商补料是两种可区分的动作；
- 商品、问题、原因、责任人和时间完整；
- 退回不伪造最终 HS；
- 供应商补料后从原任务新建版本，重新预审；
- 旧提交和旧决定仍可查看。

**当前状态：** 后端/API 已有模块验证；若页面没有两个退回入口，记录为“页面待集成”。

## S12：修改品名、规格、图片或原 HS 后重传（A12）

**目的：** 验证同一任务产生新版本，整表重新预审，不继承旧结果。

**操作：**

1. 供应商上传 V1 并完成预审。
2. 复制原 Excel，修改品名、规格、图片或供应商 HS 中至少一项。
3. 从原任务的“当前任务补料”入口上传 V2。
4. 等待 V2 解析和预审完成。
5. 对比 V1、V2 的商品行、图片、HS、置信度和执行记录。
6. 业务员确认 V2 并重新提交专家。

**通过标准：**

- V2 属于同一任务，版本号递增；
- V1 原件、结果、提交和决定保留；
- V2 整表重新预审；
- V1 结果不自动继承到 V2；
- 专家审核使用 V2 的新提交快照。

## 人工签收结论口径

- **通过：** 预期行为全部满足，证据已留存。
- **不通过：** 有明确复现步骤和实际偏差，已创建问题记录。
- **阻塞：** 缺页面、真实来源、真实样本或权限，不能用自动化测试结果替代。
- **专业待定：** 系统流程通过，但 HS、申报要素、退税率或监管条件仍需关务专家确认。

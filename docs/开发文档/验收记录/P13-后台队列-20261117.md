## 实测摘要

| 场景 | 方法 | 观察与结论 |
|---|---|---|
| 请求及时返回 | 三角色真实登录/CSRF/上传与提交 HTTP | 上传 0.331 秒返回 staged；提交 0.460 秒返回，模型在独立进程执行 |
| 两处自动触发 | 上传→预审、业务确认提交→专家核查 | 都完成三行；专家授权存在，可读取任务与提交 |
| worker 中断 | 首行模型调用阻塞时强杀 worker 进程，等待过期租约，再启 worker | 恢复完成，中断尝试保留 |
| 一行失败 | 测试进程显式让首行抛 TimeoutError | 首行三次停止，另外两行成功；技术失败未被写成业务无法确认 |
| 人工重试 | 业务员选择失败行，POST retries | 新 run 关联 parent，只一行有本轮调用；旧结果逐行对比完全不变 |
| 请求进程消失 | 单独请求进程 DB commit 后、dispatch 前 os._exit(91) | pending 可查、未投递；扫描器重投后完成 |
| Redis 中断 | 真正关闭 Redis，HTTP 上传，再启动 Redis | 上传仍成功且持久登记，恢复后后台完成 |
| 同版旧轮/V1 晚到 | 状态单测 + 真实 PG 多连接新版本写入 | 旧结果不发布，不修改新版业务阶段 |
| 重复投递争抢 | 两个 PG 连接并发处理同 run | 每行只有一个成功调用；重复投递无重复有效结果 |
| 模型调用期间写新版本 | 独立线程阻塞引擎，另一连接持 Task 锁写 V2 | 锁可获得；释放模型后 V1 结果判过期 |
| 同 revision 重跑竞争 | 两个 PG 连接同时发起重跑 | 一个创建成功，一个 stale_revision；只一轮有效 |
| 原件与快照 | SHA256 比较、专家核查 target_hs 比较 | 原件不变；核查使用已提交确认码 |

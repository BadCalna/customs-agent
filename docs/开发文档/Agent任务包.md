# Agent 任务包

版本：1.0，2026-11-13。2026-11-15 进度：P00 技术自验通过；P01 已通过 Jay 手工验收并合入 main（PR #1）；P02 第一/二批（契约 v1、mock 引擎、只读端点、组件演示壳）技术自验通过并完成 rebase 与审核修复，待 Jay 手工测试；P03 已备好派工单。此表替代旧任务图中的人工开发分工；旧 A01～L04 编号保留为范围追踪。

23 个任务包均由 Agent 执行。主控持有模型、迁移、契约和集成权；页面、文件、查询及运维实现可独立派发。一个任务包可按其交付物分多次提交，不要求一个 Agent 单轮完成。

本文件与 [任务包索引.json](任务包索引.json) 同源。所有任务遵循 [协作与交接约定](Agent协作与交接约定.md)，衔接文档的共同入口是 [开发计划](开发任务与阶段交付计划.md)、[D1](阶段0/业务与流程约定.md)、[D2](阶段0/数据与版本约定.md)、[D3](接口与页面约定.md)、[D4](Agent输入输出与证据约定.md)、[D5](阶段0/验收用例与记录.md)、[D6](运行与交接说明.md)。

编码前置允许基于已发布的 schema/fixture 开发；集成前置决定何时能接真实入口并验收。因此两个模块可互列为集成依赖，但编码依赖不能成环。主控按代码基线确认依赖，不能只看任务名称标完成。

每包统一交付代码差异、必要测试、实际验证证据和 `交接/Pxx.md`。表中路径均相对仓库，各任务按需创建；派发时在回交文件记录实际绝对工作路径。公共文件修改需主控接管，允许目录只是最大范围，不意味着可覆盖别人正在编辑的文件。

验证命令为 `make test TASK=Pxx`，由 P00/P02 建立统一入口、各包补必要检查；尚无入口时不得写“通过”。各包可增加实际子命令；命令输出、退出码、数据库/引擎模式及未执行项写入回交。纯文档修订无需编造软件测试。

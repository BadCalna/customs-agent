## 功能

- 现有调试台新增“专家核查”，保留独立预审默认行为。
- 输入待核查 HS、供应商退税率原文、贸易方向、可选退税代码及用户给定的日期/税则版本。固定样例和父运行不能被覆盖阶段或核查编码。
- `apps/agent_debug/expert.py` 复用 P18 `ExpertCheckEngine`，显式注入同一固定版本的 HS、要素、退税来源；可选消费同 release 的 `p17_regulatory`，不把监管代码台账当监管条件。
- 展示要素、图片、退税、监管四项 `matched/conflict/unknown` 与证据。第一版无图；无来源或未经复核时保持待核，不猜日期、不补 8 位码、不替人批准。
- 复用既有单次 transport、连接/凭据管理、权限、外发审批、输入加密、worker、租约、额度及清理。P18 无需语义模型时完成来源核对，模型出站为零；真实模型错误不会被引擎降级后冒充执行成功，不自动重发。
- 来源证据以哈希标识精确关联到分项。当前 C 映射只支持 HS/注释，未支持类别不造链接；相同定位的要素记录不能误链到 HS。
- 运行详情、列表筛选、复制重跑支持阶段。MOCK 明确显示为合成模拟。专家结果始终待人工复核，仅写调试记录，不修改正式任务、提交、确认或决定。

无需新增依赖、数据库模型或迁移。现有部署注册和 live 开关继续按原方式配置；本次不打开生产 live。

## 2026-11-26 PR #50 复查修正

复查先用已复核、明确有效且无附加条件的合成退税资料复现业务错误，再修改调试适配器；不改正式 P18 引擎或公共审核协议。

1. 出口退税查询与比较仅在 `direction=export` 执行。进口返回 `tax_check.applicability=not_applicable`；方向未确定返回 `direction_unknown`，两者保持 `comparison=not_compared`，不输出税率相符/冲突，不伪装成来源失败或查无。
2. HS 与申报要素继续使用用户指定的税则版本；退税、监管只使用同一申报日期，各自从固定来源解析适用版本。税则 `2026` 不再串到退税 `2026C`。无日期、日期超出窗口或版本有歧义保持待核实，不补今天。分项结果记录已解析的来源版本。
3. 详情保留 `regulatory.outcome`、`verified`、措施 `code/category` 与哈希证据引用，明确区分有监管要求、来源明确无要求、待核实。仅权威、已复核、明确非合成、日期与方向已核、无两用物项待判的来源可产生已核措施；不保留模型自由文本或猜造证件名称/链接。现有资料中心未支持监管条件的精确跳转时，页面仍可看到措施代码，并明确提示无定位链接。

调试规则版本同步递增，旧预览必须重新生成。旧运行缺少结构化贸易方向或监管信息时，页面降为待核并提示复制重跑，不沿用此前的相符标签。另修复固定样例/复制重跑时残留无效查询基准阻止浏览器提交的问题。

修正后验证：专家适配器 46 项、HTTP/worker 40 项通过；调试台整体 112 项通过，另 1 项已确认的原 Windows 凭据用例单独保留，不计为通过。既有 P18/P16 参考适配回归 125 项及 269 个子用例通过。前端 Playwright 覆盖有/无监管要求、措施代码、退税方向、旧结果降级与固定样例提交；Django check、无迁移漂移、JS 语法、diff 检查通过。原有 Windows 凭据托管问题按约定继续留待统一处理。

### 接口与执行约定

- `POST /api/v1/versions/{id}/prechecks`：`{"revision": <当前任务 revision>}`；业务员权限、当前版本和可编辑阶段校验。
- `POST /api/v1/runs/{id}/retries`：`{"item_ids": ["<明确失败行>"]}`；只能对当前、已结束执行的失败行发起。预审需业务员权限，专家核查需专家权限。
- 两者都要求登录、CSRF、`Idempotency-Key`。返回 run_id，读取 `GET /api/v1/runs/{id}` 看真实持久进度。GET 不执行模型。
- RunDetail 新增 `parent_run_id/retry_allowed/retry_item_ids`；RunItemEntry 新增 `attempt_history/origin_run_id`，排队未调用与本轮沿用成功行的 attempts 为 0。
- 人工重试创建新 Run，关联 parent；未选行沿用旧结果并保留来源。旧 Run/旧成功/失败尝试不改写。同 key 重放返回原执行。
- 保留五态 RunStatus。部分成功时 run 为 succeeded，但 progress.failed 仍如实显示失败，不能当作业务通过。
- 自动单行最多三次，失败/中断单独记账。输入哈希、领取 token、最新版本/同版最新轮次、提交有效性均在写入前复核。失效输出不成为当前结果。
- Redis 不可用或请求进程提交后退出，由持久 RunWork 和扫描器恢复；它不是仅靠提交回调的内存任务。

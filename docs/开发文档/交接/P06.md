### 业务功能与关键设计

1. 首次上传校验角色、幂等键、文件和 P04 结构；通过后暂存，事务 A 提交 Task、FileVersion、ImportJob、queued Run 和上传审计。供应商取自当前身份，不接受客户端自报归属。结构/关键识别阻断发生在创建任务前。
2. 事务 A 成功后，事务 B 锁 Task，发布原件并按 P04 直接创建 Item/ItemMember，保存页签/行/单元格、各字段原文/公式、历史意见和未识别备注；P05 处理同版本图片。成功后激活预登记的同一 Run 完成整表 mock 预审。仅 mock，不接官方来源或真实队列。
3. 分配状态 `unclaimed/claimed` 与业务阶段分开。未分配任务在解析成功后可认领；业务阶段进入待确认，仍可处于待认领。
4. 待认领池只暴露 UUID、创建时间、待认领状态。默认同一试用空间全部活跃业务员共享，`CUSTOMS_CLAIM_SCOPE_POLICY` 接收 `(user, queryset)` 可收窄。只允许最新版本解析成功且没有 operator 授权/认领的任务进入列表；此范围不授予完整资料读取。
5. 认领锁 User → Task；TaskClaim 的 one-to-one 唯一约束兜底，同事务写 TaskAssignment 和 `task.claim` 审计。多业务员竞争失败返回 409。本人重复认领重放原归属；完整读写继续按 P01 的 TaskAssignment 对象权限校验。
6. 原件/图片只通过文件 UUID 调用 P05 受控读取，不接受路径；不可见对象 404，匿名 401，图片仅 available 有下载 URL。响应 private/no-store，不返回服务器路径。
7. 同键同指纹复用同一 ImportJob/版本/Run，失败可以用同键继续；同键不同指纹 409。主动再次上传同任务已有 sha256 先提示重复文件，确认意图使用新 key 才创建新版。
8. V2 全表新建商品、装箱成员和图片，不复制旧确认、执行行或审批；旧原件、图片、确认、快照、决定保留。新版成功后旧 pending 提交变为 superseded，内容不改。任务当前执行/提交引用只取当前版本。允许从已通过任务创建新版本，新版重新待确认。
9. 图片缺失列/列歧义/图片资源读取失败保留商品，标 read_failed 和原因；无图 absent，成功 available。图片文件存储失败单独报 import_failed，不当作无图。原 HS/要素/退税率空白不阻断；原 HS 和退税率原文用 TextField 保存，避免 PostgreSQL 的 32 字符限制丢原文。
10. 结构阻断、P04 blocking_issues、缺商品品名、超出已有来源/品名/成员字段长度、成员归属争抢拒绝导入并返回来源位置。无匹配保留为 `missing_packing_member` 问题；未认领装箱行保留 `unlinked_packing_row`；同一项号多箱全部落成员。完整清单与错误例见 D3 第 10 节。

### 中断、暂存和恢复

- 事务 A 失败时 discard 暂存，测试验证无正式文件/任务。
- 事务 A 已提交、发布前/发布后进程中断：ImportJob 仍是 staged（或技术异常后 failed），预审非有效；文件发布回执可重用。
- `.venv-customs/bin/python manage.py resume_import <import_id>` 显式从同凭据继续；也可用原文件、原目标、原幂等键重试上传。不会另增版本或预审。
- 事务 B 失败时商品/成员/图片状态/执行行回滚，持久失败状态和 `import.failed` 审计留存；正式文件可能已存在，重试按内容/回执复用，不能宣称与数据库原子。
- 成功后清理暂存字节/回执/绑定，锁文件由 P05 保留；重复清理 stage_not_found 可忽略。
- **遗留**：在暂存成功、事务 A 登记前被强制杀进程，可能留下未被 ImportJob 引用的 incoming 文件。本轮没有按年龄自动清理器；部署前需补受控孤件扫描/清理。正式文件不自动删除。
- 无真实 RQ/worker、自动重扫、有限重试或服务进度推送。P13 从持久凭据接续，当前仅显式恢复命令和同步 inline。

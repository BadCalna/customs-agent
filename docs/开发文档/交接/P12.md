## 本轮完成内容

- `.env.example` 默认 SQLite，全新目录可完成 setup、migrate、check 和 WSGI 启动；PostgreSQL 通过注释模板显式启用。Django 与 shell 采用相同 dotenv 优先级：进程环境优先、关闭插值、不执行 `.env` 内容。
- SQLite 源库通过只读 backup API 生成包含已提交 WAL 的独占快照，只升级副本。未知迁移、非空未知表/列在升级前拒绝，禁止忽略 WIP 字段。
- 动态覆盖全部 managed 模型及 M2M，按 FK/M2M/自然键依赖排序；循环依赖归为同一组件，交给事务末尾约束核对。真实 Task + TaskAssignment 纳入迁移验收。
- ContentType/Permission 由目标迁移重建，引用按自然键解析。源端拒绝不可重建的元数据；目标端严格比较完整自然键集合和权限名称，额外、缺失、重命名均在复制附件及导入/flush 前拒绝。
- 严格导入全新目标，拒绝非空目标。开发场景的 `--fresh` 仍需 `CUSTOMS_PG_ALLOW_FLUSH=<精确库名>`。核对 datetime 完整微秒、浮点、全部模型/M2M 内容摘要与外键孤儿。
- 必须显式指定源附件根；目标默认当前 `CUSTOMS_FILE_ROOT`，也可单独指定。迁移前记录路径/大小/SHA-256，安全复制到独立目标目录，拒绝覆盖异内容文件及嵌套根；导入后同时核对两端。
- P12 备份入口接入 P22。native 在实际备份期间持有同机附件写入锁、PG 表/序列锁，并将导出快照交给 pg_dump；前后核对内容及身份，释放锁成功后才生成 COMPLETE。拒绝 `--no-quiesce`，锁冲突或任何失败均无 COMPLETE。
- 完整恢复只写入全新数据库/文件根，核验内容、schema、sequence、文件指纹和目标身份。manifest 覆盖 dump、附件归档、清单和一致性元数据四项；旧三项 manifest 不再被新版接受。
- 本机 trust 集群 init/start/restart 仅接受单个回环 IP；拒绝通配符、非回环或多监听地址。macOS 使用 mmap/posix 共享内存和短 socket 路径；旧 DB-only restore 永不删除已有库。

## 回退与部署约定

1. native 不管理应用生命周期，但实际持有 PG 表/序列及同机附件协作锁，配合导出快照与前后完整指纹比较。启用前须重启应用/worker 到新代码；旧进程、手工/跨主机/绕过 storage 的写入及 DDL 仍须运维停止。备份失败无 COMPLETE；回归均使用独立测试库/临时根。
2. PG 尚无新写入时，可以切回原 SQLite 与原文件根。PG 已接受业务后，回旧 SQLite 会丢失新增内容；应保全完整 PG + 文件备份，恢复到独立 PG 目标并验证后切换连接。
3. 本地 trust 与 CREATEDB 只服务开发和 Django 测试。共享部署按 D6 配置认证、应用最小权限和建恢复库的运维角色。
4. 新补强 PR 需要评审合并；历史 PR #11 的 merged 状态不代表本轮分支已经合并。

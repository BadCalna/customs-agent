## 本轮完成内容

- 推荐 PostgreSQL 配置，Django 与 shell 脚本采用相同 dotenv 优先级；进程环境优先、关闭插值，不执行 `.env` 内容。无后端配置时仍支持 SQLite 快速开发。
- SQLite 源库通过只读 backup API 生成独占快照，包含已提交 WAL；只升级副本。未知迁移、非空未知表/列在升级前拒绝，禁止通过忽略字段搬走 WIP 数据。
- 自动遍历所有 managed 模型，包含 P06 导入/认领、用户组、管理员日志、Session 和全部 M2M。ContentType/Permission 由目标迁移重建，引用按自然键解析；不能重建的自定义/旧元数据即使未被引用也明确拒绝。
- 严格导入全新目标；拒绝非空目标。开发场景的 `--fresh` 必须额外提供 `CUSTOMS_PG_ALLOW_FLUSH=<精确库名>`；不再接受无明确授权的清空。
- 保留 datetime 完整微秒和浮点精度，比较所有模型及自动 M2M 的内容摘要、行数和外键孤儿。自动 through 表比较关系内容，不依赖其生成 ID。
- 在接触 PG 前保存附件路径/大小/SHA-256 清单；导入后重新核对。缺文件、路径越界、符号链接逃逸或同路径同大小内容变化均失败。
- P12 备份入口接入 P22 native 数据库 + 完整文件目录备份；失败不返回部分成功。完整恢复只写入全新数据库和文件根，核验内容、schema、sequence、文件指纹及目标身份。
- macOS 本机集群使用 mmap/posix 共享内存和短 socket 路径，支持带中文的长仓库路径。旧 DB-only restore 永不删除已有库，并明确说明其不包含附件。
- 增补迁移保留/拒绝回归及 P10 多连接并发决定测试；`make check-postgres` 覆盖 P12/P05/P06/P09/P10，使用非交互测试库操作；双库脚本任意一端失败均非零退出。

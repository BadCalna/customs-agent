### 关键设计

1. **结构上防误用**：结果类型不是 `RecommendOutput`；候选字段是 `historical_hs`，没有
   `hs`/`suggested_hs`；`reference_only` 为 `Literal[True]`，构造 `False` 直接校验失败；
   `RecommendOutput(candidates=result.candidates)` 会因缺少 `hs` 报错。以上均有测试锁定。
2. **四态绑定**：`OUTCOME_EVIDENCE_STATUS` 是唯一映射，结果校验器强制
   `matched→obtained`、`no_match→not_found`、`query_failed→query_failed`、
   `invalid_query→null（未发起查询）`；`matched` 必须有候选，其他状态不允许带候选。
3. **规则可复算**：`score = 0.6×品名词元 Jaccard + 0.4×属性一致率`；缺品名/缺要素各自
   打 0.8 折；存在差异乘 0.7 惩罚。`matched_keys`/`diff_keys`/`unverified_keys` 独立输出，
   差异不因总分高而消失。
4. **历史时间与来源原样保留**：`recorded_at`、`source.document`、`source.locator`、
   `source.url` 直接透传；解析时间只用于 `age_days`/`stale`/过期提示，解析失败则留空，
   不改原值。
5. **存储可替换**：`HistoryRecordStore` 协议只需要 `load() -> HistorySnapshot`。
   `JsonHistoryStore`（默认）、`InMemoryHistoryStore`、任意带 `load()` 的对象均可接入；
   文件缺失/JSON 损坏/记录不合契约统一转 `query_failed`，不静默吞成空候选。
6. **合成数据明确标注**：数据集声明 `synthetic=true`；证据标题带“（合成样本，非真实历史库）”，
   未声明来源则写“（数据来源未声明）”，不默认信任。

### 后续 Agent 从哪一步继续（P16 接入说明）

1. **构造一次，复用**：每个预审执行构造一个 `HistorySearchSource`（`load(path)`、
   `HistorySearchSource(records=...)` 或自定义 `store=`），不要每行新建。注意
   `JsonHistoryStore` 每次 `search()` 会重读文件，批量场景可在外层包一个缓存 store。
2. **输入**：从商品事实构造 `HistoryQuery(name, elements, spec, material, attributes)`；
   不要把供应商原 HS 传进来，也不要传执行上下文/当前结论。
3. **分支处理**：
   - `matched`：用 `result.evidence_status`（`obtained`）和 `result.to_evidence_entries()`
     把历史记录挂成**证据**；`historical_hs` 只能进候选说明/参考区，不能写入
     `suggested_hs`，也不能塞进 `RecommendOutput.candidates`（会校验失败）。
   - `no_match`：记 `not_found`，**不要**按查询故障重试或报错；可以没有历史证据继续预审。
   - `query_failed`：记 `query_failed`，按 P13 决定是否重试；不能降级成“没查到”。
   - `invalid_query`：属于输入构造问题，不应重试；修输入后重新构造。
4. **差异必须透传**：把 `diff_keys`、`key_attribute_conflict`、`similarity_note` 带进
   issues/理由；`key_attribute_conflict=true` 时不得判“与历史一致”。`version_status`
   恒为 `version_unverified`，`stale`/`validity_note` 要展示给业务员/专家。
5. **live 模式闸门**：P16 真实模式应拒绝或显式标注 `dataset.synthetic is not False` 的
   历史证据；默认构造就是合成样本，未配置真实路径时不能产出“真实历史命中”。
6. **比较结论**：复用 P02 `compare_original` 的判定顺序，不要为历史证据另写一套。
   历史记录 `obtained` 只说明“记录取到了”，不等于“编码有效/与当前税则一致”；
   版本未核实应按 D4 保持待核。
7. **落库/审计**：P15 不写库；若 P16 要保存历史证据，按 `EvidenceEntry` 存储并保留
   `recorded_at` 原值与 `source` 定位，不要用查询时间覆盖历史业务日期。

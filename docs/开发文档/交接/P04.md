## 关键设计决定

1. **一条申报记录=一个商品**。商品行只取申报要素页签的一行；装箱行数只决定成员多少，
   不按装箱行数计商品，也不和装箱页签按相同行号对齐（关联键只有 `合同号+项号`）。
2. **语义表头定位，不写死列字母**。表头匹配做全半角/大小写/全部空白/括号说明归一；
   除完全相等外只接受“别名＋括号说明”，不做包含匹配（避免把“英文品名”当成“品名”、
   “中文单位”当成“单位”）。真实模板的列位置只作为观察记录，不进入代码常量。
3. **同义重复列不随便取一列**：必填列（合同号、项号、品名、海关编码、申报要素）重复直接抛
   `duplicate_semantic_column`；可选列与 AI/人工结果列重复则记 `ambiguous_semantic_column:<字段>`
   警告并整体丢弃该字段（两列原文仍以“未识别列”逐行保留），等待主控确认别名后补。
4. **原文与来源分开**。每格给 `value`（未 strip 的原文）、`cell`（当前格或纵向合并锚点）、
   `column`、`header`、`formula`（共享公式从属格从 `Sheet.formulas` 取有效公式）、
   `from_merge_anchor`。原 HS 空白就是空字符串，异常原值原样保留，已有意见原样保留。
5. **横向合并不借列**。纵向合并只在同一列取锚点（复用 `ooxml.Sheet.value_at` 的口径），
   横向合并的空格不借用相邻列内容，避免把邻列字段当成这一列的值。
6. **行识别继承 P03**：有项号/品名或强事实（海关编码、申报要素、附图、规格、厂家型号、
   物料代码）或附图列内精确单格浮图 → 记录；整行只有“汇总本表前序区域”的公式 → `summary_formula_only`；
   写成“合计/总计/小计” → `summary_row`；只有合同号或说明文字 → `contract_only_or_footer`/`note_only`。
   退税率列里的说明文字（真实模板在退税列下方写要素名）不算商品事实。
7. **只按缺失/歧义给状态**。记录级问题只有身份字段缺失：申报 `contract/item/name`、装箱
   `contract/item/primary_name`；`status` 取 `identified`/`requires_review`。
   **原 HS / 申报要素 / 退税率空白不判成 P04 问题**（原文空白就是数据，由 P06/D4 的业务校验处理）。
8. **合并申报展开是词法展开**：`1-3`、`1、2、3`、`1；3` 展开为成员；范围保留原文前导零宽度
   （`01-03` → `01/02/03`），不做数值改写（`01` 与 `1` 不当同一项）；倒序、跨度过大、无法解析、
   同一行重复项号一律报问题，不静默展开。
9. **冲突绝不任选**。同一合同项被多条申报行认领 → `member_claimed_by_multiple_declarations`
   （列出认领的申报行号，两条都标待核并互给 `conflicting_declaration_rows`）；同 key 多条装箱行事实不同 →
   `same_key_different_facts`（列出装箱行号与差异字段），成员全部保留；未匹配 →
   `missing_packing_member`；没人认领的装箱行 → `unlinked_packing_row`。
10. **问题可定位**。统一 `Issue(code, message, sheet, cell, row, field, details)`，行级问题都落在
    页签+单元格；结构级问题抛 `SemanticLayoutError(code, sheet, cell, field, details)`，
    表示“结构读不出”，不能当成“0 个商品”继续。
11. **输出对齐 P06 模型**：`DeclarationLink.item_values()` 的键与 `reviews.Item` 已有字段对齐
    （`source_sheet/source_row/source_cells/name/attributes/supplier_hs_raw/supplier_elements_raw/
    supplier_tax_rate_raw`），`member_values()` 的键与 `reviews.ItemMember` 对齐
    （`relation_type="packing"/source_sheet/source_row/contract_no/item_no`）。
12. **只读与副作用**：不写库、不发通知、不调模型/网络；工作簿在内存中只读，原件字节不变。

### 地基 API 是否够用

够用，未改 `adapters/files/ooxml.py`，也没有绕过代码。用到的是：
`Workbook.find_sheet`（页签前缀按包含匹配）、`Sheet.value_at`（纵向合并取锚点、横向不借列）、
`Sheet.formulas`（共享公式从属格的有效公式，`Cell.formula` 在从属格为空）、
`Sheet.merged/cells/occupied_rows`、`Workbook.picture_anchors`（附图列内精确单格浮图，
用于发现“只有图片、没有文字”的申报行）。图片资源解码、DISPIMG 定义表留给 P05。

## 来源与差异（对照 P03 `experiments/excel_fidelity/mapping.py`）

语义继承、代码重写：生产代码**不 import experiments**。从 P03 试验提炼进 `adapters/files` 的部分：

| P03 试验 | P04 生产实现 | 说明 |
|---|---|---|
| `ALIASES` / `RESULT_ALIASES` / `normalized` / `field_matches` | `declarations` 的别名表与同名函数 | 别名集合按 P04 字段表扩充（`existing_opinion`、`merge_hint`），保留别名+括号说明匹配口径 |
| `detect_layout` 的表头行与重复列判定 | `locate_layout` + `_choose_header_row` + `_unmapped_columns` | 增加必填列缺失诊断、同义重复列分级处理、未识别列清单 |
| `value_at`（自行实现合并锚点） | 复用 `ooxml.Sheet.value_at` | 纵向合并取锚点、横向不借列；增加 `from_merge_anchor` 标记与公式来源 |
| 行分类（商品/汇总/表尾/图片候选） | `extract_records` + `_summary_reason` + `evidence_fact` | 判定顺序与 P03 一致；“退税率列文字不算事实”固化为独立函数 |
| `parse_items` | `packing_links.parse_items` | 拆分问题码：`reversed_item_range`/`excessive_item_range`/`unparsed_item_list`/`duplicate_item_in_list`/`missing_item`；新增 `packing_item_not_atomic` |
| `map_workbook` 的成员关联 | `link_declarations` + `map_workbook` | 保留分箱/合并/多认领/同 key 不同事实口径；问题从字符串变为带位置的结构 |
| `map_images` | 未搬迁（归 P05） | P04 只定位附图列、保留 DISPIMG 公式文本与附图来源单元格，并发现“只有浮图的行” |

主要差异（需要 P06/主控知道）：

1. **状态取值**：P03 关联状态为 `linked_by_contract_item`/`requires_review`；P04 按验收口径统一为
   `identified`/`requires_review`，记录级与关联级各有一个 `status`，入口给 `DeclarationLink.status`
   （记录问题 + 关联问题合并判定）。
2. **项号问题码拆分**：P03 的 `ambiguous_or_excessive_item_range` 拆成 `reversed_item_range`、
   `excessive_item_range`（另有 `unparsed_item_list`、`duplicate_item_in_list`、`missing_item`），
   真实样本原先归在该码下的倒序项号现在是 `reversed_item_range`。
3. **新增字段**：`existing_opinion`（已有意见/历史意见）、装箱 `merge_hint`（合并申报），
   以及 AI 结果四列 `ai_hs`/`confirmed_hs`/`confidence`/`precheck_conclusion` 的定位与原文保留；
   缺列进 `missing_column:<字段>` 警告，不占其他列。
4. **未识别列**：布局级给列清单（表头、是否有数据），行级给有值的单元格（原值+公式），
   真实模板中“无表头但有内容”的已有意见/OK 列因此能原样保留，不被当成空列覆盖。
5. **结构化属性**：申报要素按 `｜`/`|` 与 `：` 拆成有序条目（`label`/`value`），只做拆条，不判断
   要素是否符合该 HS、不补缺失要素、不做归类。
6. **P06 映射**：P03 只给报告字典；P04 增加 `item_values()`/`member_values()`，键与
   `reviews.Item`/`reviews.ItemMember` 对齐（`version`/主键由 P06 补）。
7. **图片**：P03 的 `map_images` 行级图片状态未搬迁；P04 只提供 `record.facts["image"]`
   （附图列原文/公式/单元格）、`floating_image_cells`（附图列内精确单格浮图）与
   `record.image_cell`，图片能否取出由 P05 判定（R11：读不出≠没有）。

## 未验证项与限制

1. **P06 未落库**：`item_values()`/`member_values()` 只是字段形状对齐，未经过模型 `clean()`、
   唯一约束（`Item(version, source_sheet, source_row)`、`ItemMember(item, relation_type, sheet, row)`）
   与事务回滚验证；商品修订、图片状态未接。
2. **P05 未接**：附图只保留 DISPIMG 公式文本/来源单元格；图片资源是否存在、能否解码、
   `available/absent/read_failed` 的判定都在 P05，P04 不把“读不出”当“没有图”。
3. **真实样本有限**：只覆盖上述 3 份（同一供应商模板系列）；别名集合按 P03 观察到的表头整理，
   其他供应商/历史版本模板可能出现未识别表头（会以 `missing_required_columns` 或缺列警告暴露，
   不会静默错列）；未做压力/大文件测试，未做模糊测试。
4. **合并申报真实展开未验证**：真实样本只有 1 份含“合并申报”列，且其中的项号本身没有范围，
   展开逻辑只在合成样例上验证。
5. **真实样本未出现“同一合同项被多条申报行认领”**：该冲突只在合成样例验证；
   同 key 不同事实与倒序项号在真实样本各 1 处，已按“只报问题不选一条”处理。
6. **行级非商品分类是启发式**：汇总公式行/合计行/说明行/表尾行的判定继承 P03 规则，
   未覆盖“整行只有条件公式”“合并单元格跨越数据区”等结构；遇到会进记录并标待核，不会静默丢弃。
7. **结构化属性只是拆条**：申报要素按分隔符拆成条目，不校验要素是否符合该 HS，也不补要素。
8. **未做独立验收**：本包只有模块自验与真实样本只读核验，未委托独立审查 Agent。

## 给 P06 的接续说明

- 入口：`adapters.files.packing_links.map_workbook(workbook)`（内部先 `extract_packing`、
  `extract_declarations`，再 `link_declarations`）；也可分步调用以复用布局。
- 落库映射：
  - `link.item_values()` → `Item`（`version` 由 P06 填；`attributes` 直接存 JSON；
    `supplier_hs_raw`/`supplier_elements_raw`/`supplier_tax_rate_raw` 是原文，空白保留空字符串）。
  - `link.member_values()` → `ItemMember`（`relation_type="packing"`；只含已命中的装箱行；

  - `link.record.source_cells` → `Item.source_cells`；`link.record.sheet/row` → `Item.source_sheet/source_row`。

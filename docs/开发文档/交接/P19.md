```http
GET /api/v1/messages?limit=20&unread_only=false
-> {"items": [...], "next_cursor": null, "unread_count": 1}

PATCH /api/v1/messages/{message_id}
X-CSRFToken: <本次登录会话令牌>
Content-Type: application/json

{"is_read": true}
```

GET 不标已读、不投递；PATCH 只允许 true，重复请求保留首次 read_at。他人/不存在/畸形 UUID 均为 404；未登录为 401，缺 CSRF 为 403。分页排序 created_at、UUID 均降序；极端时区日期在解析期转 UTC 并拒绝溢出，返回 400。

消息 DTO：message_id、task_id/version_id/submission_id/decision_id（可空）、kind/title/body、is_read/read_at、created_at、target_url。任务权限已撤销时消息仍属于原收件人，但 target_url 为 null；直接目标 API 仍复查权限。

### 节点和收件人

| 节点 | 收件人 | DWS |
|---|---|---|
| 新提交 | ensure_submission_expert 选出的具体活跃专家 | mock |
| 专家通过 | 原提交业务员、任务供应商 | 仅业务员 mock |
| 专家退回业务员 | 原提交业务员 | mock |
| 专家退回供应商 | 任务供应商 | 不登记 |
| 业务员退回 | 任务供应商 | 不登记 |

不按角色广播，不猜未认领任务业务员。本批节点与任务包输入场景一致，未额外增加“上传后给所有业务员提醒”等新规则。每次新业务事件登记独立消息；请求幂等重放和同内容 pending 提交重放不重复登记。绑定来自服务端业务对象，不接受客户端指定收件人/事件/目标。

### 事务、重试与边界

- 业务事务内写入 Message 和 outbox，事务回滚时一同回滚；提交后尝试投递。提交与回调之间进程退出时由持久扫描恢复。
- 投递在数据库锁外；领取使用行锁与 CAS、60 秒租约、随机 token。写回同时校验 token、状态和有效租约。已过期的旧领取者不可覆盖新结果。
- 每条最多 3 次，明确失败在 30×已尝试次数秒后可重试。中断尝试保留 interrupted；第三次中断耗尽，不发第四次；无租约的异常 processing 记录可扫描恢复。
- 失败仅保存固定 error_code，不保存异常正文。inactive/失去任务权限的收件人以及 disabled 模式均 suppressed。mock 成功只为 mocked，不是 delivered。
- `CUSTOMS_NOTIFICATION_MODE=mock`（默认）或 `disabled`，其他值启动失败。本批未建立真实 DWS 通道，不能把 mock 收据视为真实投递或外部 exactly-once 保证。
- Message.save 校验绑定不被重写，并保留父对象删除后的 SET_NULL 语义；公共接口只可改已读。普通 ORM QuerySet 不承诺通用不可变边界，维护脚本不可自行重绑消息目标。

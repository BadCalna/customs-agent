# P15 历史模板导入（最小流水线）

状态：**模块自验通过，PR #23 待审**（2026-11-17）
分支：`feature/P15-history-import`
基线：`main@176aa8d`（`data: archive authorized customs import basis snapshot`）
PR：[#23](https://github.com/BadCalna/customs-agent/pull/23)

本页只说明“历史业务 Excel → P15 可读取历史记录”的导入流水线。它**没有**接入
PostgreSQL、没有改 P06 的上传服务/业务 API/页面/任务认领/公共模型，也没有把历史
成功记录当成当前归类结论。

## 1. 目标与范围

已实现：

- 复用 P04 的 `map_workbook()`（申报要素提取 + 装箱关联）与 P05 的
  `extract_column_images()`（DISPIMG/浮图判定）。
- 提取：品名、原 HS、申报要素键值、规格/材质、图片状态、文件/页签/行号/
  合同号/项号/单元格范围、原申报要素原文。
- 转换为 P15 `p15.history.1` JSON；输出 P15 可直接用
  `HistorySearchSource.load(path)` 读取。
- 输出导入报告（JSON + Markdown）：文件级解析失败、逐行缺字段、P04 关联问题、
  图片状态、重复/变化、人工声明、真实/合成标记。
- 重复导入：稳定 `record_id` + `source_key`；同内容重复跳过、内容变化报告并
  默认保留旧记录（`--replace-changed` 才替换）；批内重复也报告。
- 查询验证：自动生成 hit / no-match / key-attribute-diff 三个用例，调用 P15
  适配器并把结果写入报告。

不包含：

- 数据库、迁移、PG、权限、租户隔离、上传链路、页面、任务认领。
- 真实检索效果评测、阈值校准、HS 版本/有效期核验。
- 海关放行凭证、报关日期、税则版本等模板中不存在的信息：**不生成、不推断**。

## 2. 数据契约与接口

### P15 契约（先读后写）

- `contracts/schemas/history/HistoryRecord.json`：`record_id`、`historical_hs`、
  `historical_name`、`recorded_at`、`source` 为必填；`elements` 是当时申报要素；
  `outcome` 只有 `approved/passed/放行/通过` 会进入历史成功案例。
- `HistorySearchResult` 是参考结果，不是 `RecommendOutput`；候选字段是
  `historical_hs`，`reference_only=True`。
- `JsonHistoryStore` 接受
  `{"schema_version": "p15.history.1", "dataset": {...}, "records": [...]}`；
  记录不合契约会变成 `query_failed`，不会静默当成空库。

### P04 / P05 实际接口（未修改）

- `adapters.files.packing_links.map_workbook(workbook, declaration_label="申报要素",
  packing_label="装箱明细")`
  - 返回 `DeclarationMemberMap`：`declaration.records`、`links`、`issues`、
    `blocking_issues`。
  - `SemanticRecord` 提供 `value(field)`、`cell(field)`、`raw`、`attributes`、
    `source_cells`、`unmapped`、`floating_image_cells`。
  - `DeclarationLink.issues` 与 `conflicting_declaration_rows` 用于报告关联歧义。
- `adapters.files.dispimg.extract_column_images(workbook, sheet_name, column, rows, header_row)`
  - 返回 `ImageExtraction`，逐行 `RowImage.status` 为
    `available/absent/read_failed`；列本身不可用时 `column_status` 为
    `missing/ambiguous`，不会伪装成“无图”。
- P04 没有把“图片列缺失”当 row 级状态，因此导入层额外使用
  `column_missing/column_ambiguous/row_missing` 三个导入状态，不写入 P05 的状态枚举。

本包**没有修改** `adapters/files/*`、`apps/*`、`contracts/*`、`Makefile`、
`pyproject.toml`/锁文件；改动只在 `adapters/sources/history_import.py`、
`scripts/import_history_templates.py`、`tests/p15/*` 与本页。

## 4. 输出与字段口径

输出目录默认 `data/private/p15-import/<storage_key>/`（Git 忽略；`storage_key` 只含来源身份，不含文件哈希，因此同一模板重新保存后仍写回同一目录，重复保护默认生效）：

| 文件 | 内容 |
|---|---|
| `history_records.json` | P15 `p15.history.1` 快照 |
| `import_report.json` | 完整报告（含逐行明细、重复、声明、策略） |
| `import_report.md` | 人读摘要 |
| `query_validation.json` / `.md` | hit/no-match/key-attribute-diff 验证 |
| `images/` | 仅 `--copy-images` 时可用的图片；文件名含 `record_id` + sha 前缀，避免同名覆盖/错关联 |

关键字段：

- `record_id` = `HIST-` + SHA256(`source_id|sheet|row|contract|item`) 前 20 位；
  同一文件重复运行稳定。
- `source_key` = `source_id|sheet|row|contract|item`，用于识别“同一来源位置内容变化”。
- `source`：`document=source_id/原始文件名`，`locator=页签!第N行；合同…；项号…；单元格…`，
  `system=historical-template-import`（真实）或 `synthetic-history-template`。
- `attributes`：合同号、项号、数量、单位、退税率、`elements_raw`、图片状态/单元格/
  sha256/格式、来源文件哈希、批次、成功依据、问题码。P15 允许 `attributes` 为
  `dict[str,str]`，因此全部值按字符串保存。
- `hs_version` / `applicable_scope` / `valid_until`：模板没有就保持 `null`，不推断。
- `recorded_at`：只从模板中明确的“申报日期/报关日期/业务日期/日期”列读取；
  找不到就写固定占位符 `未提供`，并在 `attributes.recorded_at_missing=true`、
  `notes`、报告 `missing_fields` 中三处标注。**没有用文件名中的日期、合同号里的日期
  或归档日期补日期。**
- 图片状态：
  - `available`：图片可读，记录 `image_cell`/sha256/格式/大小；
  - `absent`：图片列存在但该行没有图片；
  - `read_failed`：有图片线索但读不出（缺媒体、坏资源、公式形态不支持等），**不等于无图**；
  - `column_missing` / `column_ambiguous`：整列不可用，不能按无图处理（ambiguous 为防御性分支）；
  - `row_missing`：列可用但该行没有返回结果，按未取得处理（防御性分支）。

## 5. 重复导入处理

- 运行前读取同目录已有 `history_records.json`（`--fresh` 时才忽略）。
- 同 `record_id` 且业务字段相同：`duplicate / kept`，不重复写入。业务字段不含
  文件哈希、批次号、输出路径；同一模板重新保存但业务内容没变，不会把所有行都算成变化。
- 同 `record_id` 或同 `source_key` 但业务字段变化：`changed / kept_existing`，默认保留旧记录；
  加 `--replace-changed` 才替换并记 `replaced`。
- 批内同 `record_id/source_key`：`duplicate_within_batch / skipped`，保留首条。
- 不同来源文件（复制/改名）但业务内容相同：`duplicate_business_content / skipped`，
  默认不重复写；显式 `--keep-business-duplicates` 才保留多份来源。业务去重需要
  合同号或项号至少一个；两者都为空时只按 `record_id/source_key` 去重，不跨来源
  推断重复（该行本身会标 `needs_review`）。
- 真实/合成输出不允许混在同一 JSON；不一致直接报错，要求换目录或 `--fresh`。
- 重复/变化均写入 `import_report.json` 与 Markdown，不静默。

## 7. 查询验证（P15 实际返回）

`query_validation.json` 的 `checks` 三态均通过：

| case | 期望 | 实际 | 结果 |
|---|---|---|---|
| hit-basic | matched + 指定 record_id | matched，候选 1（真实）/4（合成） | 通过 |
| no-match | no_match，不是 query_failed | no_match，候选 0 | 通过 |
| key-attribute-diff | matched + 关键属性冲突 | matched，候选含 `diff_keys` 与 `key_attribute_conflict=True` | 通过 |

真实数据验证：扫描 86 条，明确成功 86 条；hit 返回 1 条候选；no-match 为
`no_match/not_found`；关键差异返回 1 条候选并带差异。合成数据验证：扫描 6 条，
hit 返回 4 条（同名/同要素的合成重复样本），no-match 0 条，关键差异 4 条。
历史成功码只作为参考，验证结果不代表当前归类正确。

## 9. 未完成事项 / 风险

1. **P15 `recorded_at` 必填 vs 模板无日期**：P15 合同 `recorded_at` 为
   `minLength=1`，三份真实模板都没有申报日期。本包用 `未提供` 占位符并报告缺失，
   没有编造日期。若要严格保留空值，需要公共契约调整（**未在本 PR 修改**）：
   - `HistoryRecord.recorded_at` 允许空字符串/`None`，或增加 `recorded_at_missing`
     显式布尔；
   - `HistorySearchSource` 对空日期返回 `age_days=None`、`stale=False`、提示缺失；
   - 影响：`contracts/schemas/history/*`、`adapters/sources/history_search.py`、
     P16 历史证据展示；需要契约版本与 P16 回归。当前 `未提供` 在 P15 中表现为
     日期不可解析，不会伪造业务日期。
2. **未接 PostgreSQL / 未落库**：输出是 JSON 快照。以后接库实现
   `HistoryRecordStore.load()` 即可，不需要改检索器；但需要先定表结构、来源哈希
   唯一约束、权限与迁移。本 PR 不声称已接数据库。
3. **H02 有一条 P04 blocking `reversed_item_range`（第 12 行，项号 `55-27`）**：
   历史导入没有整份拒绝，而是导入该行并写 `attributes.needs_review=true` 与
   `attributes.blocking_issue_codes`，同时报告 problem；这是“历史资料可回看”与
   P06“上传闸门”的不同口径。是否应在历史导入时也拒绝该行，需 Jay/主控确认。
4. **P04 的 `parse_elements` 是朴素拆条**：真实 H01 的 `0:标签|值` 写法会被拆成
   序号/标签错位；本导入层没有改 P04，而是用自己的 `parse_element_pairs` 处理两类
   真实写法。若后续要统一，建议把该解析提升到 P04，另做回归；本 PR 未侵入。
5. **图片只记录/可选复制，没有图片存储去重**：`--copy-images` 按
   `record_id` + 图片 sha 前缀命名，冲突时拒绝覆盖并记入 `image_copy_failures`，
   不再让整份文件误判解析失败；没有做跨记录图片去重或 P05 存储绑定。
6. **真实成功状态未独立核验**：来自 Jay 的人工声明；不是海关放行凭证、不是 P06
   审核状态。检索结果只能作为参考。
7. **检索效果未评测**：P15 的 R-07/R-08/R-09 仍存在；本 PR 不做阈值调优或效果声明。
8. **P06 未触碰**：没有改上传服务、业务 API、页面、任务认领、公共模型；后续若要
   把历史记录挂到商品卡片，需要 P06/P16 通过公开接口接 `HistorySearchSource`。
9. **未处理模板改版**：同一 `source_id+sheet+row+contract+item` 内容变化会报
   `changed`，但不会自动判断“旧记录应删除还是保留”；默认保留，需人工确认后
   `--replace-changed`。
10. **未做多文件同名 source_id 冲突检测**：manifest 的 H01–H03 唯一；任意文件按
    stem 生成 source_id。业务内容相同的复制/改名文件现在会被业务指纹识别为
    `duplicate_business_content`；若两个同名但内容不同的文件同批导入，需要检查
    source_id 后再换 `--out-dir` 或改名。

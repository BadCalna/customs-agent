## 交付物

### 1. ReferenceBundle

文件：`adapters/engines/reference_bundle.py`

- `ReferenceBundle.load(config)` 只接受显式 `release_dir` / `published_dir` 或进程环境变量；未配置时不搜索默认目录、不回退合成样本。
- `published/current` 只解析一次并固定 release 目录；之后不重新穿过 current 指针，避免激活竞态混版。
- 逐一校验发布 `release.json.files` 声明的文件、字节数、SHA-256、发布指纹、真实批次及数据类别；拒绝路径穿越、缺文件、未声明文件和内容/指纹漂移。
- P14 HS 与申报要素版本窗口必须一致；退税和注释版本独立保留，不错误要求 `2026 == 2026C == commentary batch`。
- `real + unreviewed` 默认可读用于技术接入，但来源仍非权威；`require_reviewed=True` 才拒绝未复核。`synthetic` 不是 `False` 时拒绝真实 bundle。
- 历史源默认 `None`；只有显式历史 JSON/store/source 才创建，绝不读 P15 默认合成 fixture。
- 输出固定 `bundle_id/version/fingerprint/source_metadata` 和 P14/P17/P15 可注入 source。

### 2. CommentaryReferenceSource

文件：`adapters/engines/commentary_reference.py`

- `retrieve(candidate_codes=(), keys=(), keyword="", expected_version="")` 与 `lookup(key, expected_version="")`。
- 10 位候选只映射到确定层级材料：4 位品目、可确定的章/类边界；77 章、98/99 等不猜类；8/10 位直接作为层级 key 查询会拒绝。
- 返回原始完整 sections、定位、版本、数据集状态与证据；总正文上限默认 24,000 字符，超限只省略完整分段并标记 `truncated/omitted_sections`，不半截正文。
- 永远区分 `material_retrieved` 与 `classification_support=False`；不生成 `ClassificationNote`，不把“查到注释”自动升级为“支持该 10 位编码”。
- 版本未给或不匹配时，即使查无记录也返回 `version_unverified`；只有显式匹配快照版本才可返回 `not_found`。
- 所有失败原因使用固定安全文案；不透传路径、异常正文或秘密。对外 `authoritative` 要求 `synthetic is False`，未知真实性 fail-closed。

### 3. SkillPrecheckAdapter

文件：`adapters/engines/skill_precheck.py`

- 读取项目已有 `docs/skills/steel-hs-declaration/SKILL.md`，只选择 `stage=precheck` 的商品关联和预审规则，记录原始 Skill 与选段 SHA-256；专家审核、图片和 Excel 写回不进入本适配器。
- `build_request(...)` 是离线 dry-run，不调用模型。默认按固定目录的名称/别名词元召回最多5条，规格仅辅助排序；保留算法版本、扫描/匹配/遗漏计数与截断标记，明确不是完整候选集合。`candidate_codes=()` 可禁用召回。召回码进入 P14 和对应注释检索，模型可以提出集合外候选。
- `recommend(...)` 只调用一次注入的 `model.complete`，再对模型候选做 P14 HS/申报要素后验核验。Skill 摘录移除本地 Excel/网站读取指令，执行仅使用供应的资料包，不赋予模型外部工具权限。
- 输入只保留事实白名单；供应商原 HS、任务/版本/商品/运行 ID、路径、秘密、图片元数据不进模型。图像明确标记 `not_connected`。
- 历史查询整体后移：模型请求中只保留 `deferred_until_after_independent_recommendation` 和空记录，不包含历史 HS。严格模型解析通过后才查显式历史源，匿名 `reference_only` 结果仅增加后验差异/待核信息，不回改建议、不再次调用模型；真实性必须明确为非合成。注释材料保留 `classification_support=False` 和版本/来源状态。
- 模型坏 JSON、来源失败、来源响应身份不匹配均为固定技术失败；不把查无、查询失败或版本待核改写成供应商补料或成功。
- 来源材料与事实长度预算分开：来源完整原文按注释总预算处理，10,001/20,000字完整段不再因事实10k限制被拒绝；事实仍限10k。超预算按完整段省略并明示，敏感标记与hidden值在完整字符串上检查，不分块漏检。
- 保守拒绝事实中的任意 POSIX/Windows/UNC 路径、路径分隔符、URL 及任意长度执行ID（含1–3字符）。这种保守策略也可能拒绝带斜杠的正常规格表达；不是一般化脱敏工具，后续应在明确字段语义下优化，不能悄悄放宽。

- 本轮只实现“文本预审候选生成”子集，不是完整业务 Skill：最新 Skill 的退税初核、钢材成分合计、语义高/中/低等级及 Excel 写回尚未接入。公共比较枚举仍按已发布 D4 的“同码缺依据为 needs_confirmation”，不因 Skill 文档新表述自行修改公共契约；正式接线前由主控统一处理规则差异。

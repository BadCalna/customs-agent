## 关键设计决定

1. **比较结论以 D4 为准，模型同步改**。P01 落的五类与 D4 六类不一致（缺“原码缺失”，命名不同），
   经 Jay 确认按 D4 改模型并出数据迁移，而不是在 schema 层做有损映射。
   回滚时 `supplier_missing` 只能并回 `invalid_original`，已在迁移注释标明有损。
2. **`is_current` 是版本维度，不是任务维度**。初版按任务维护导致 V1 商品的执行引用全为 `null`，
   V1 历史结果在卡片上不可见，违背 FIX-09。改为按版本维护后，V1/V2 各有当前执行，
   同版本重跑才把旧一轮转为历史；`RunItem.clean` 原本就强制商品属于执行的版本，跨版本串数据无通道。
3. **阶段值为 `null` 仍保留来源引用**。“执行过但没建议”与“还没执行”必须可区分，
   因此 `StageValue{value:null, source_id:<run_id>}` 是合法且必要的响应。
4. **推荐输入从结构上防锚定**。`RecommendInput` 没有 `supplier_hs_raw` 字段，
   由测试断言其 JSON Schema 中也不存在；申报要素原文可能自然出现编码，记入 `anchoring_notes`，
   不声称删一个字段就消除锚定风险。
5. **比较优先级只写一份**。`compare_original` 按“关联异常 → 原码缺失 → 原码异常 →
   资料或证据不足 → 一致/不一致”判定，同码缺证据仍为 `needs_confirmation`，
   来源不可达只记待核、不据此判编码无效。P16 真实引擎应复用而非另写。
6. **样例由真实序列化生成**。FIX 文件来自演示数据的 ORM 序列化结果，与 live 响应同构；
   顶层未用字段省略，内部 `null` 一律保留。
7. **同路径 501 必须同 router**。Ninja 按路径先注册者优先，`POST /tasks` 若放在独立占位 router
   会被 `GET /tasks` 判 405，因此该占位注册在 `read.py`，并有测试锁定。
8. **写请求先过 CSRF 再谈 501**。已登录缺令牌是 403 `csrf_failed`，带令牌才是 501；
   匿名写请求是 401。三档都有测试。
9. **fixture 与 live 同构，不做第二套假数据**。`DEMO-SET.json` 由真实 ORM 序列化，
   `tests/p02/test_web_shell.py` 直接拿 live 端点响应做等值断言；序列化器一改而没重导，
   测试就红。导出不写 `generated_at`，同数据重导字节一致，不制造无意义 diff。
10. **晚到响应靠令牌 + 身份双保险**。版本/商品切换后旧请求可能先发出后到达，
    只用令牌拦截不够——令牌已变但数据已写入；因此每次 await 返回后同时校验
    `token` 与响应自带的 `version_id`，两层都过才写 store。
11. **演示静态资源不挂 static/ 也不引 CDN**。`web/` 在仓库根，Django 不会自动服务；
    用受控视图而非 `django.views.static.serve`，顺带拿到后缀白名单与路径穿越防护，
    页面为原生 ES module，无构建、无外网依赖。

## 未执行与已知限制

- **演示壳不是正式页面**：P02 只交付查看入口，`web/app.js` 渲染的是只读卡片与行；
  真正的页面交互、表单、上传与审批流程由 P07/P08/P11 重写，届时替换 `web/` 即可，
  `api.js`/`state.js` 的请求令牌与错误分类口径可直接复用。
- **演示壳不实现写动作**：上传、确认、提交、退回、决定、导出按钮点击只提示 501；
  `allowed_actions` 只展示，服务端仍每次重新校验。
- **fixture 模式不校验权限也不写库**：它只能看组件形状，不能当作接口可用性证明；
  验证权限、越权 404、CSRF 必须用 live 模式或 `manual_check.py`。
- **写动作未实现**：上传、版本创建、确认、提交、退回、决定、重跑、重试、导出、下载、消息均为 501。
  `Idempotency-Key` 持久化与 409 冲突检测未实现，FIX-08 只是错误形状样例。
- **真实引擎未接入**：只有 mock。置信度 0.62 是固定演示值，未校准，不能当作准确率；
  所有编码与依据都是合成样例，证据条目 `source_type=synthetic`、`document=MOCK-ONLY`。
- **图片与文件下载未提供**：`ImageEntry.download_url` 恒为 `null`，受控下载由 P05 交付。
- **inline 无恢复保证**：`apps/runs/inline.py` 由命令/测试显式调用，不是后台队列；
  事务内同步执行，进程中断的恢复、重试与过期保护由 P13 负责。
- **分页游标未签名**：只是排序键的 base64 编码，不承载权限；每次翻页仍重新校验可见范围。
- **列表 `allowed_actions` 只按角色矩阵**，未叠加任务阶段规则（P06/P09/P10 补充），
  服务端仍每次重新校验，前端不得据此放行写动作。
- **跨版本对照未实现**：FIX-09 只保证旧版本可读与前端丢弃规则，未做合同号/项号的商品对照（P10/P11）。
- **P01 分支协调（合并前必须处理）**：本分支含 `runs.0002_comparison_status_d4`、`runs.0003_run_current_per_version` 两个迁移。
  截至本回交时，P01 工作区已出现未提交的 `apps/runs/migrations/0002_protect_historical_inputs.py`
  与 `apps/reviews/migrations/0003_protect_historical_inputs.py`，**与本分支的 `runs.0002` 编号冲突**。
  Django 对同一 app 的两个 0002 会报 conflicting migrations，不能直接合。
  处理顺序：P01 先提交并合入 → 本分支 rebase → 把本分支两个 runs 迁移重编号为 0003/0004，
  `dependencies` 改指 P01 的 `0002_protect_historical_inputs`，再用空库重跑 `make migrate` 与 `make test TASK=P02`。

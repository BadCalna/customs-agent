## 关键设计决定

1. **图片状态三分，失败原因细分**。`available` 只在媒体部件存在、像素解码通过且未超限时给出；
   `absent` 只在“单元格确实没有图片公式”时给出（细分 `blank_cell` / `text_content` / `other_formula`）；
   其余全部 `read_failed`，错误码区分 `dispimg_definition_missing`、`dispimg_definition_duplicate`、
   `dispimg_media_missing`、`dispimg_media_corrupt`、`dispimg_media_external`、`dispimg_decode_not_run`、
   `dispimg_media_too_large`、`dispimg_expression_not_evaluated`、`dispimg_multiple_references`、
   `dispimg_formula_unsupported`、`dispimg_formula_text_only`。**读不出不会写成无图片**。
2. **共享公式逐行解析**。从属行本身没有公式文本，按 `ooxml.Sheet.formulas` 的主公式平移结果解析；
   若从属行缓存值里带着本行自己的 `DISPIMG` 调用（WPS 写法），以缓存值为本行实际 ID，
   `id_source` 标记 `formula` / `shared_formula` / `shared_formula_cached`，并在 `notes` 留追溯说明。
3. **条件/表达式公式不推断显示结果**。`IF(...,DISPIMG("ID",1),"")` 之类的公式返回
   `read_failed + dispimg_expression_not_evaluated`，只列出候选 ID，不把候选图片入库；
   一个单元格多个引用单独用 `dispimg_multiple_references`，与“条件公式”分开。
4. **图片列识别只用表头关键词**（附图/图片/照片/image/picture/photo），不按固定列字母；
   多个候选返回 `ambiguous` 并列出候选列；识别失败时服务层返回 422，**不会**写一批 `absent` 冒充结论。
5. **内容寻址 + 版本目录**。原件落 `tasks/<task>/versions/<version>/original/<sha256>.<ext>`，
   图片落 `.../images/<sha256>.<ext>`；新版本重新解析、不沿用旧目录，跨版本不会串图。
6. **原子写入、不覆盖**。临时文件 `fsync` 后用 `os.link` 独占发布；目标已存在时只允许内容一致
   （幂等复用），内容不同报 `storage_content_conflict`；文件系统不支持硬链接时退回 `O_EXCL` 独占创建。
7. **文件名只作展示元数据**。展示名经 NFKC、去路径分隔符/控制字符、截断超长、规避 Windows 保留名、
   拒绝危险扩展名；落盘名不用原文。相对路径解析拒绝绝对路径、`..`、反斜杠、盘符冒号、控制字符与
   符号链接逃逸（realpath 后必须仍在存储根内）。
8. **不可变**。`storage.delete()` 显式抛 `immutable_storage`；本包不提供修改/删除入口。
9. **服务层不依赖 HTTP**。保存用 `UPLOAD_VERSION`（供应商本人、必须是最新版本），读取用 `READ`；
   对象不存在/不可见抛 `Http404`，动作不允许抛 `PermissionDenied`，未登录抛 `AuthenticationRequired`；
   对外只给字节与净化后的展示名、相对路径，不暴露服务器绝对路径。
10. **同版本重跑按 `(item, source_cell)` upsert，主键稳定**。已存在记录只更新
    `status/dispimg_id/storage_path/error_message/extracted_at`，`ItemImage.pk` 不变，旧图片 ID 仍能读到
    同一张图；不存在才新建。本次解析未出现的旧 `source_cell` 记录删除，过滤条件始终带
    `item__version_id=version.pk`，未涉及商品行与旧版本记录原样保留。
11. **不开放用户提图入口**。按 Jay 口径删除 `extract_version_images(user, ...)`，只保留系统入口
    `extract_version_images_for_version(version, ...)`：不接收 user、不做权限校验，由 P06 在已授权的
    上传/解析流程内调用，调用方必须保证版本与商品行归属。当前没有任何角色可以手动重跑图片提取；
    未来若开放手动重跑，需同时校验版本（只允许最新版本）与任务阶段，不能只校验任务可见性。
12. **存储配置已落到 settings**。`CUSTOMS_FILE_ROOT`（默认 `BASE_DIR/.local/files`，相对路径按仓库根解析）、
    `CUSTOMS_FILE_MAX_BYTES=104857600`、`CUSTOMS_IMAGE_MAX_BYTES=20971520`、
    `CUSTOMS_FILE_READ_MAX_BYTES=209715200`；环境变量可覆盖，非正整数解析失败直接抛
    `ImproperlyConfigured`。服务层仍用 `getattr(settings, ...)` 读取，测试用 `override_settings`。
    `.env.example` 与 D6 已同步说明。
13. **单格浮图只认精确锚点**。单元格没有 DISPIMG 公式时，只把“起止锚点都落在本行图片列
    同一单元格”的普通浮图当作该行图片：单张且像素解码通过 → `available`，
    `id_source`/`formula_status` 为 `single_cell_floating_anchor`、`dispimg_id` 留空；
    多张 → `read_failed + floating_image_multiple`，坏资源/缺资源/解码未通过 →
    `read_failed + floating_image_unavailable`，超限沿用 `dispimg_media_too_large`。
    跨行、跨列、表外浮图不参与行归属，不就近猜。同一单元格同时有 DISPIMG 公式和浮图时
    以公式结果为准，并在 `notes` 写明浮图待人工核对。
14. **暂存原语（方案 A）**。`stage_bytes` 把上传字节写 `incoming/<uuid>.<ext>`（同样校验大小、扩展名、
    路径），`publish_staged_original` 用独占发布落到版本原件路径并清理暂存字节，保留小体积发布回执
    （`incoming/<token>.json`）用于重复发布幂等；重复发布返回同一正式路径（不覆盖、不换主键）。
    **暂存与发布使用同一个 `max_bytes`**（发布参数默认 `DEFAULT_MAX_BYTES`，服务层两处都取
    `max_original_bytes()`），发布阶段仍再校验一次，避免“暂存成功后换小上限失败”。
    并发发布同一 token 时先查回执；读暂存遇到已被另一调用清理时回查回执，清理 `FileNotFoundError`
    视为对方已完成，两个调用都返回同一正式路径且只写一份文件。
    `discard_staged` 只删暂存区内的合法 UUID（含回执），拒绝任何正式路径。
    P06 应按“暂存 → DB 事务提交 → 发布”编排，事务失败 discard，避免孤件与半个任务。
16. **服务层暂存系统入口**。`stage_version_original(data, *, filename)` 按 settings 上限暂存并返回
    token；`publish_staged_version_original(version, token, *, filename)` 按同一上限发布并写
    `FileVersion.storage_path`（仅未设置时写入；已设置不同路径返回 409，不覆盖）。两者都不接收 user，
    P06 必须已在上传流程完成权限与归属校验。
15. **导出副本统一存取**。`save_export` 落
    `tasks/<task>/versions/<version>/exports/<kind>/<sha256>.<ext>`，后缀白名单
    `.xlsx/.xlsm/.csv/.pdf/.zip`；`read_export`/`export_exists` 只接受 `exports/` 路径并复用受控读取。
    导出业务（生成内容与业务引用）仍由 P20 负责，服务层暂不接入。

建议编排顺序（P06 负责事务、幂等键、事件与端点；P05 只提供下列服务函数）：

1. 上传端点先校验权限与文件，再调用
   `files.stage_version_original(data, filename=...)` 落暂存（内部按 `CUSTOMS_FILE_MAX_BYTES`）：
   - 返回 `token/sha256/size`，此时**还没有正式原件**；暂存目录 `incoming/` 不属于任何版本；
   - 底层也可直接调用 `storage.stage_bytes(root, data, suffix=".xlsx", max_bytes=...)`，但必须与发布上限一致。
2. 在同一数据库事务里创建 `Task` + `FileVersion`（`original_filename` 用上传原名）与商品行：
   - 事务失败或业务校验失败 → 调用 `storage.discard_staged(root, token)`，不产生正式文件；
   - **事务提交后**调用 `files.publish_staged_version_original(version, token, filename=...)`：
     服务层按同一 settings 上限发布、写 `FileVersion.storage_path`，已登记不同路径返回 409；
     同一 token 并发/重复发布都返回同一正式路径，不覆盖、只产生一份原件。
3. 如果暂时不上暂存方案，也可直接调用
   `files.store_version_original(user, version_id, filename=..., data=<bytes>)`：
   - 只接受任务最新版本（旧版本 409 `stale_version`），版本归属由 `require_action(UPLOAD_VERSION)` 校验；
   - 同字节重复上传幂等返回原 `storage_path`，不同字节 409 `original_already_stored`；
   - 但它在 DB 事务外写盘，事务回滚会留下不可删除的文件；正式接上传时应优先用暂存方案。
4. 解析商品行并创建 `Item`（P06 的解析任务）；`Item.source_sheet` 必须与提取时传入的 `sheet_name` 一致。
5. 商品行落库后调用系统入口
   `files.extract_version_images_for_version(version, sheet_name=..., rows=..., column=...)`
   （不接收 user，调用前 P06 已在写流程内完成权限与归属校验）：
   - 行与列建议直接取 P04：`mapping = map_workbook(workbook)`，
     `rows = [link.row for link in mapping.links]`，
     `column = mapping.declaration.layout.columns["image"]`；组合用法见
     `tests/p05/test_p04_p05_compose.py`；
   - 只有系统入口，不存在用户手动重跑入口；重跑按 `(item, source_cell)` upsert，主键与旧图片 ID
     保持稳定，不要为了重跑先删 `ItemImage`；
   - `column=None` 时按表头关键词识别；返回 422 `image_column_missing` / `image_column_ambiguous` 时，
     应记解析问题/待人工核对，**不要**把它当成“该版本全部无图”；
   - 返回报告含 `counts`、逐行 `status/code`、`storage_path`、`skipped_rows`；图片状态直接用于卡片
     `image_status`，`download_url` 仅对 `available` 非空。
6. 下载端点（`GET /files/{file_id}` 或版本/图片专用路由）调用
   `files.read_version_original` / `files.read_item_image` / `files.read_item_image_path`：
   - 服务层已做 `require_action(READ)`，API 层把 `Http404`/`PermissionDenied`/`AuthenticationRequired`
     转成 D3 的统一错误体，不要另写一套权限；
   - 不要返回绝对路径；相对路径只用于内部拼下载路由或审计。
7. `ImageEntry.download_url`（P02 契约）由 P06/P20 接线，P05 未改契约与演示壳。
8. 存储根：`settings.CUSTOMS_FILE_ROOT`（默认 `BASE_DIR/.local/files`）；测试用
   `override_settings(CUSTOMS_FILE_ROOT=<tmp>)`，settings 由主控维护，模块测试不直接修改。
9. 上传端点仍建议使用 `Idempotency-Key`：本包的保存/提取是内容级幂等，不能替代“同一次上传请求只创建一个版本”。

## 对 D6（运行与交接说明）的建议

- 配置已落地到 `config/settings.py` 与 `.env.example`：`CUSTOMS_FILE_ROOT`
  （默认 `BASE_DIR/.local/files`，位于 `.local/` 已被 Git 忽略）、`CUSTOMS_FILE_MAX_BYTES=104857600`、
  `CUSTOMS_IMAGE_MAX_BYTES=20971520`、`CUSTOMS_FILE_READ_MAX_BYTES=209715200`；
  非正整数环境变量解析失败会启动报错，不静默回退。
- 目录结构：`tasks/<task_uuid>/versions/<version_uuid>/original/<sha256>.<ext>`、
  `.../images/<sha256>.<ext>`、`.../exports/<kind>/<sha256>.<ext>`；导出已按同层内容寻址落盘，
  P20 只负责生成内容与业务引用。暂存区在 `incoming/`，只允许 P06 发布或丢弃。
- 不可变与保留：原件/图片/导出副本不提供业务删除入口；只有 `incoming/` 暂存区可由 P06 发布或丢弃，
  正式目录清理必须停写 + 备份 + 审计，禁止由代码批量删除。
- 备份/恢复：数据库与文件必须一起备份（D6 已要求同一时点）；文件只增不删，可做增量备份；
  恢复后按 `storage_path` 重新核对 sha256，丢失的单列出来而不是静默重建。
- 权限：进程创建的目录/文件应为 0700/0600；存储根不得放进静态资源目录或任何 Web 可直读路径。
- 跨平台：不支持硬链接时会退回独占创建（已实现并测试）；Windows 路径分隔符与保留设备名在
  文件名净化中处理，但正式部署仍建议 Linux 文件系统。

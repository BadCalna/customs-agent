## 4. 身份设计

汇总表没有唯一主键；报关单号一个可对应多条商品，合同项号缺失，不能把
“报关单号”或“整份文件哈希”当每行主身份。

默认身份：

```text
content_hash = SHA256(规范化后的业务字段 JSON)
record_id    = "HISTC-" + SHA256(source_id | content_hash | 同内容出现序号)[:20]
```

- 参与内容的字段：供应商、采购合同号、合同号、报关单号、HS、中文品名、英文品名、
  申报要素、规格、材质、税收分类代码、进项税率、出货情况、箱号、提单号、备注、放行情况；
  可选列存在时还包含项号、数量、单位、退税率、明确业务日期、原文件和原行。
  规范化仅折叠常见显示空白，不删除词内空格、不转换大小写；原文列单独保存。
- 排序、插行、重新保存不会改变 `content_hash`；行号不进入身份。
- 整份文件 SHA-256、批次 ID、行号、单元格范围只作溯源；重新保存不会导致全部商品变新。
- 同 HS+品名但规格/材质/申报要素不同 → 不同 `content_hash`，保留为不同记录。
- 完全相同的两行 → 用 `content_occurrence=0/1` 区分，保留两行，报告同内容组。
- 可选的 `original_record_id` 列若存在、非空且唯一，优先作为身份；重复/空值会报告
  并退回内容哈希。
- 变更配对使用 `change_anchor`（供应商+采购合同号+合同号+报关单号）：先匹配所有
  完全相同的记录，只有同锚点恰好“1 条旧缺失 + 1 条新内容”才配对为 `changed`；
  多候选记 `identity_uncertain`，保留 `missing+added`、标待核，不按行号/排序猜替换。
  `business_key` 用于同业务键内容冲突；`change_key` 保留作诊断，不用其序号强配。
- 数据集及每条记录写入 `identity_version=p15.consolidated.identity.2`。未发布旧候选
  缺版本/版本不同时普通 merge **拒绝**，避免身份算法升级造成整批新增；需显式
  `--fresh` 重建。发布器保留旧 generation，不自动物理删除旧快照。

稳定边界（已知）：

1. `source_id` 默认取文件名 stem（或 manifest `source_id`）。**改名后会被视为新来源**；
   需要保持身份时用 manifest 固定 `source_id`。
2. 同一报关单/合同下多条商品共用锚点；多条同时变更无法可靠配对时，只报告
   `identity_uncertain + missing + added`。即使开启替换，也不会强配；报告保留旧记录。
3. 修改业务字段会产生新内容身份；能可靠单候选配对才报告 `changed`，默认保留旧记录，
   显式 `--replace-changed` 才替换。完全重复行只有 occurrence，可稳定保留数量和 ID 集合，
   但不能知道被删除的是其中哪个现实商品。
4. 汇总表本身没有日期，`recorded_at` 固定为现有占位符 `未提供`；不是稳定业务日期。

## 5. 图片与日期口径

- 汇总表没有图片列，也没有媒体部件。图片状态全部记 `column_missing`，**不能当作
  所有商品都无图**；不声称从旧模板恢复了图片。
- 若后续汇总表增加图片列：
  - DISPIMG/浮图复用 P05 `extract_column_images`；
  - `available/absent/read_failed/row_missing/column_ambiguous` 分开；合并图片续行
    `read_failed + image_merged_continuation`，不跨行借图；
  - 外部 URL 默认不联网，状态 `external_url_not_fetched`；
  - 本地路径默认不读，只有显式 `--image-root` 才读取根目录内文件，并拒绝
    `..`、绝对路径、符号链接越界（`external_path_unsafe`）；复用 P05 像素解码并限制
    大小，坏图片为 `read_failed`，不以文件后缀冒充可用图片；
  - 复制图片按 `record_id + sha 前缀` 命名，同名异内容拒绝覆盖；图片消失时清空
    当前引用/哈希/大小，旧 generation 的图片实体保留，不静默借旧图。
- `recorded_at` 仍为 P15 必填的 `"未提供"` 占位符；不从文件名“历史成功数据”、
  合同号中的日期、归档时间或导入时间补日期。
- `hs_version/applicable_scope/valid_until` 保持 `null`；历史 HS 只作参考，不写
  `suggested_hs`、不产生当前审批结果。
- 文件名“历史成功数据”不等于海关放行凭证；成功口径来自批次人工声明，
  `independently_verified=false`。

### 发布完整性

- JSON、报告和验证先写完整隐藏 generation；顶层稳定链接经过 `.current` 指向
  `.snapshots/<id>`，仅一次原子切换指针提交。已有平面输出安全迁移，旧 generation 保留。
- 真实子进程 `SIGKILL` 在准备/迁移/提交前后注入：提交前旧快照可读，提交后新快照完整。
- 图片内容寻址先发布，同名异内容拒绝；图片复制/记录写入失败不会切换指针。
- 发布锁内做 SHA-256 CAS：解析/合并所用旧记录字节与当前不同就拒绝，避免并发覆盖。
  失败后需重新读取合并，不能仅重发旧候选。普通异常清理 staging，诊断留在顶层。
- `validate` 也发布新 generation；`--skip-validation` 明确写 `status=skipped`、
  `all_passed=false`，不会把旧成功验证误当本轮通过。
- 要同时读取多个文件，应先固定 `(out_dir / ".current").resolve()`，再从同一代读取。
  分次打开顶层文件可能跨越一次提交；不宣称跨 open 的事务一致性。
- 退出码：0=导入完整且已执行的检查通过；1=部分拒绝/冲突、检查失败或技术中断；
  2=参数/格式/身份版本/来源集合不合法。`needs_review` 单独报告，不伪装全体可检索。

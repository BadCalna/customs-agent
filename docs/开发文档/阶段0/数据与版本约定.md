# D2 数据与版本约定（阶段 0 简版）

文档编号：D2。对应总计划「六份衔接文档各管什么」：[开发任务与阶段交付计划](../开发任务与阶段交付计划.md)。本文件为阶段 0 简版，阶段 1 和阶段 5 验证后更新。

版本：0.2，2026-11-13。状态：已按 Q01～Q07 的答复更新：商品行改按申报要素页签维度、补料不带 ID 且整表重审。模板与 DISPIMG 读取待真实工作簿核对；业务规则以 [业务与流程约定](业务与流程约定.md)（D1）为准。

本稿先说明对象、字段含义与对应关系，不提前锁定数据库类型、接口和全部字段。模板映射来自已有说明，实际工作簿尚未在本轮直接读取核验。

## 先分清四件事

| 对象 | 含义 | 当前状态 |
|---|---|---|
| 审核任务 | 一个上传的 Excel 文件对应一个审核任务，包含多条商品记录 | R01、R07 已确认；补料在原任务入口重传 |
| 文件版本 | 某次上传的原文件及解析结果 | B08；同一审核任务下用 V1/V2 区分补料版本 |
| 商品行 | 按申报要素页签维度建立，一条申报记录对应一个商品行 | R05 已确认；同时保存与原 Excel 的位置关系 |
| 分析执行 | 对某输入版本进行的一次预审或专家 AI 核查 | 内部运行记录；同一审核任务可有多轮；专家核查在业务员提交后自动触发 |

Excel 行号描述文件里的位置，商品 ID 描述被管理的记录，两者分开保存。业务员提交给专家的内容还应有一份提交快照，固定文件版本、商品修订和待审 HS。

## HS 怎样保留

R02 已确认留存需求；以下“阶段结果＋修改日志”是实现建议。无需每跑一次 AI 就新增一组数据库列，可按商品、文件版本、审核环节和执行次数保存独立结果。

| 内容 | 建议保存方式 | 用途 |
|---|---|---|
| 供应商原 HS | 每次上传版本按原文保存 | 查看供应商当时提交什么，保留空白及异常原值 |
| 业务员预审 AI 建议 | 每次预审执行独立保存，含候选、原因和证据 | 保留 AI 在该输入条件下的判断 |
| 业务员确认/提交 HS | 编辑记录＋提交快照 | 专家实际审核的 HS；未明确时不可静默用 AI 值代替 |
| 专家 AI 核查结果及编码建议 | 对应专家执行记录独立保存 | 与业务员提交值比较，保留专家环节 AI 的不同意见 |
| 专家人工确认 HS | 人工审核记录关联提交快照 | 保存最终人工决定；专家可直接改码后通过（R08），前后值与原因必须留痕 |
| 修改日志 | 商品、环节、版本、操作者、时间、前值、后值、原因 | 解释什么时候由谁修改；AI 生成建议和人工采纳分别记录 |

页面直接展示关键阶段值，历史通过执行记录和日志查看。AI 建议不覆盖供应商原码，复制或重传不复制通过权限。

## 现有多页签模板：语义映射草案

依据：[现行模板字段说明](../../skills/steel-hs-declaration/references/business-template.md)、[网页端功能要点](../../网页端功能要点.md)、[模板适配说明的当前口径](../../实际业务模板与Skill适配说明.md)。参考模板由 Jay 提供至 docs，本表待按真实工作簿核对；旧列字母及历史行数仅为观察，不作固定解析规则。

| 页签/区域 | 字段含义 | 系统用途 | 保存与待核点 |
|---|---|---|---|
| 装箱明细 | 合同号、合同项号 | 跨页签关联线索 | 按文本保留；重复、分箱或合并时保存成员关系，不能假定唯一 |
| 装箱明细 | 合同第一条品名 | 主品名 | 原文保留；真实表头和起始行待工作簿核对 |
| 装箱明细 | 附件清单品名 | 别名、检索和消歧 | 与主名分开；缺列或冲突如实标明 |
| 装箱明细 | 规格、厂家/供应商提供型号 | 商品归类事实 | 分字段与来源保存；不能固定用 R 等列，型号列可能不存在 |
| 装箱明细 | 物料代码、数量、单位 | 辅助对应与事实核对 | 不仅凭同名或相同数量自动合并 |
| 申报要素 | 合同号、项号或合并成员 | 定位申报条目 | 与装箱行保存明确映射，不按两页签相同行号对应 |
| 申报要素 | 海关编码 | 供应商原 HS | 原文及来源单元格保存，不覆盖 |
| 申报要素 | 附图 | 关联商品的可见事实输入 | 读取该行附图列并入库；图片为 WPS DISPIMG 机制，需按工作簿内嵌入资源解析；读不出单独提示，不得当作无图片（R11） |
| 申报要素 | 供应商申报要素、退税率 | 专家核查输入 | 原文保留，AI 建议另存；空白不自动补成无或零 |
| 申报要素 | 已有审核意见及无表头但有内容的列 | 历史上下文和导出保留 | 不当作空列覆盖；旧“OK”不直接作为当前通过状态 |
| 箱件汇总及其他页签 | 原模板现有内容 | 当前原文件与导出保留 | B10：本期不增加包装汇总核对；真实页签名称与保留特性待核验 |
| 申报要素 | 拟申报日期 | 证据适用时间的参考 | 系统不填写、不自动生成（R12）；导出保持原样 |
| 申报要素新增/复用列 | AI推荐HScode、预审结论 | 预审输出 | 紧邻原海关编码右侧依次插入，原右侧列随之移动 |
| 专家结果区 | 核查、建议要素、置信度及待核问题 | 专家辅助与结果展示 | 页面按“商品行＋卡片”展示（R12）；未执行时显示未执行，不填通过结论 |

工作簿核对清单：实际页签名、表头/数据边界、已有结果列、合并单元格、普通内嵌图片或 WPS DISPIMG 图片引用、公式、已有意见。核对后补充准确位置，不把旧文件的 L/M/Y 等字母写死；DISPIMG 需实际打开图片部件验证可读性。

## 附图与 DISPIMG 怎样存取

申报要素行的附图列存放的是 WPS 的 DISPIMG 公式（形如 `=DISPIMG("ID_…",1)`），图片实体不在单元格里，而在工作簿内部的图片资源与 cellimages 映射中。常规读取只能拿到公式文本，需按映射取出图片并另存。建议保存：商品行 ID、文件版本、页签、单元格、图片资源标识与保存路径、提取状态（已提取/未提取/失败）、提取时间。提取失败必须单独记录并在页面提示，不能按“无图片”继续判断。

## 商品 ID 和位置怎样对应

每个文件版本分别记录：审核任务标识、文件版本标识、商品行 ID、申报要素页签中的行与单元格范围、附图引用，以及关联的装箱明细成员行及原始位置。关联类型用于区分装箱分配与申报成员。

商品行主记录取申报要素页签的一行（R05）；同一申报条目关联多条装箱记录时，作为成员列表保存。合并申报、分箱时保留成员关系，不强行拆成与 Excel 行一一对应的记录；是否进一步拆分待真实模板核对后决定。

## 跨版本对应：不带 ID、整表重审

Q02、Q03 已决定：补料文件不携带系统商品 ID，供应商从原审核任务入口重传，导入后直接对它进行重新预审。

- 导入即整表重审：新版本的所有商品都重新执行预审，不继承上一版的预审或审批结论。
- 不做行级复用判断：首期不区分“未变/受影响”商品，避免因无法可靠识别而行级串结果。
- 对照仅作展示：按合同号、项号、型号及位置生成新旧版本对照，供页面并排查看；对不上时如实标注，不阻断重审。
- 旧结果保留为历史：旧版本的预审、提交和专家结论都保留可查，但不对新版本生效（B08）。
- 图片和合并关系随新版本重新解析，不沿用旧版本的图片映射。

例子：G001 在 V1 位于装箱明细第 8 行，V2 排序后到第 15 行。系统按合同号＋项号在页面并排展示两版位置，但 V2 仍整表重新预审，G001 不因位置变化自动获得旧结论。

## 补料后的处理口径

首期统一规则：任何补料重传都整表重新预审，旧审批不自动沿用。

| 修改 | 预审处理 | 专家处理 |
|---|---|---|
| 排序/位置变化 | 整表重新预审 | 对新提交版本重新审核 |
| 商品身份、规格、型号、材质、用途、图片或 HS 等归类输入变化 | 整表重新预审 | 业务员重新确认 HS 后整批提交，专家重新审核 |
| 仅补证据、确认不影响归类 | 仍重新预审（首期不判断复用） | 重新进行专家核查及人工处置 |
| 新增、删除、拆分或合并商品 | 导入后按申报要素行重新建立商品记录 | 不自动继承旧审批 |

行级的“受影响范围判断”和“有效预审复用”作为后续优化，待跨版本识别可靠后再引入；在此之前不承诺未变商品保留结论。

执行失败、来源未取得、低置信度、人工退回分别保存，避免一个状态字段混合表达。

补充依据：2026-11-13 用户确认一个文件对应一个审核任务；专家审核业务员确认并提交的 HS；保留商品行 ID 与 Excel 行的映射；首版支持现有多页签模板。补料文件不携带系统 ID、导入后整表重新预审；商品行按申报要素页签维度建立；专家 AI 核查在业务员提交后自动触发。

## 1. 本轮评估与范围

这版流程已经明确了起终点、三类角色、两次审核、原值保留和退回循环，可以作为开发主线。开发应先验证 Excel 数据能可靠进出、人工流程能闭环，再分别接入两阶段 AI，最后完成版本影响判断和真实业务验收。

- 本期主线：
  - 采购合同完成 → 供应商上传现有多页签 Excel → 上传解析后自动 HS 预审 → 业务员确认 HS 并退回或提交指定版本 → 专家获得 AI 核查建议 → 专家人工通过或退回 → 留存专家确认版本。

- 当前范围包括供应商、业务员、专家的网页操作；不增加一次物流审批。合同完成作为业务起点，不自动等于首版需要 ERP 接口。专家通过后的交接、报关发送、单证生成及对外通知不在当前流程内。原文件留存服务于本系统的版本追溯，不扩展为上游材料溯源管理。

需要贯穿开发的约束：

- 上传完成解析、关联和版本留存后自动启动预审；保留手动重新预审入口。
- 一个文件对应一个审核任务。预审执行、专家 AI 核查执行、专家人工审批分别记录，避免与用户看到的审核任务混淆。
- 供应商原 HS、原要素、原退税率保留，AI 建议与人工确认值另存。
- AI 先独立形成归类建议，再与供应商 HS 比较。同码但关键证据不足仍为“待确认”。
- 查询失败、运行失败、商品判断不确定分别记录；来源未核清时不能评高置信度。
- 导出不触发退回或发送；AI 建议不直接改变人工审批状态。
- 所有结果绑定输入版本；旧版通过不自动成为新版通过。

## 2. 已确认口径与待设计问题

下表区分用户已经确认的规则与实现建议。阶段 0 只需先把这些规则、模板字段和少量例子说清楚，再逐步形成开发所需的字段及接口细节。

| 问题 | 当前口径 | 为什么影响开发 |
|---|---|---|
| 任务粒度是什么？ | 已确认：一个文件＝一个审核任务，文件中含多条商品行；商品行按申报要素页签维度建立。补料从原任务入口重传并追加文件版本；首期不允许部分商品先通过。 | 决定任务列表、文件版本归属、商品问题及任务状态汇总。 |
| 专家到底审哪个 HS？ | 已确认：专家审业务员确认并提交的 HS。用户要求保留原始、各环节 AI 建议及修改历史。实现建议：保存关键阶段值/快照，并追加修改日志，记录前后值、操作者、时间、原因和版本；多次 AI 执行结果分别保留。 | 页面能直接展示各阶段值，历史又能说明谁在何时为什么改动；专家输入来自提交快照。 |
| 同一商品换行、排序、拆行后怎样识别？ | 已确认：保存商品行 ID 与所在版本 Excel 页签/行/单元格/图片的映射；首期不跨版本继承身份。补料文件不携带 ID，导入后整表重新预审，仅按合同号、项号、型号和位置做展示对照。 | 不做行级复用判断，避免识别不可靠时串结果；跨版本对应只用于页面并排查看。 |
| 哪些修改需要重新预审？ | 已确认：任何补料重传都整表重新预审，旧预审与旧审批不进入新版本。行级“受影响范围判断”和有效预审复用作为后续优化。 | 首期不区分未变商品，避免识别不可靠导致行级串结果；“只补申报要素”仍要检查是否影响归类。 |
| 支持哪些 Excel？ | 已确认：支持现有多页签模板即可。装箱明细、申报要素及其他页签的读取和保留范围，以真实模板为准。 | 影响解析、跨页签关联和导出保真；不预设模板只有两个页签。 |

跨版本只做展示对照，不承担身份继承：新旧版本按合同号、项号、型号和申报要素行位置生成对照，供页面并排查看；对不上时如实标注，由人处理。是否引入稳定的跨版本标识，待后续需要行级复用和差异判断时再定。

## 3. 六份衔接文档各管什么

以下是各阶段应维护的文档清单及最小目录。D1/D2/D5 的简版已在 `阶段0/` 起草，仍待共同修订及真实模板走查；其余文档待对应开发阶段建立。文档随功能增量更新，避免先写一套详设再脱离实现。

| 编号与建议文件名 | 必须包含的内容 | 谁提供 / 谁使用 | 何时成为后续依赖 |
|---|---|---|---|
| D1 `业务与流程约定.md` | 本期边界；角色权限；正常与退回路径；状态转换；审核任务汇总；五项口径决策及未决项 | 产品或业务负责人维护，开发和关务共同使用 | 阶段 0 首版；阶段 2/4/5 跟随实现更新 |
| D2 `数据与版本约定.md` | 数据字典；商品稳定标识；现有模板多页签与图片映射；关键阶段 HS 值和修改日志；版本快照；修改影响与复用规则；Excel 兼容限制 | 开发维护，页面、Agent、测试共用 | 阶段 0 简版；阶段 1 和阶段 5 验证后更新 |
| D3 `接口与页面约定.md` | 页面操作对应的请求/响应示例；任务进度；权限检查；错误码；重复提交处理；提交和审批绑定的版本 | 开发维护，前后端或 AI 编码会话交接使用 | 阶段 2 建立，之后按接口变化更新 |
| D4 `Agent输入输出与证据约定.md` | 预审与专家核查的不同职责；输入/输出示例；工具能力；证据结构；失败状态；模型/规则版本；可做和需人工决定的操作 | Agent 开发与关务共同维护，页面及测试使用 | 阶段 3 预审部分；阶段 4 扩充专家部分 |
| D5 `验收用例与记录.md` | 样本编号和版本；输入；专家预期；系统实际；通过/失败；问题记录；复验；AI 质量和限制 | 开发提供技术证据，业务专家确认业务结果 | 阶段 0 建样例；每阶段追加记录；阶段 6 汇总 |
| D6 `运行与交接说明.md` | 环境配置项；启动与停止；任务处理；模型和查询源配置；文件/数据库备份恢复；失败重试；已知限制 | 开发提供，实际维护者验证 | 首次可运行时起草；阶段 6 完成演练 |

衔接时交付当前文档版本、可运行入口或调用方式、样本输入、输出实例、验收记录和已知问题。只有“完成了”的口头说明不足以接续开发。

## 4. 分阶段总表

“进阶标准”指进入后续依赖阶段的验收门槛。可提前准备后续资料；未通过的依赖不能标记已完成。

| 阶段 | 可演示结果 | 核心交付物 | 交给下一阶段的文档 | 进阶标准 |
|---|---|---|---|---|
| 0 把基本规则说清楚 | 拿现有模板说明谁做什么、数据怎么认、改后怎么审 | 一页基本规则、模板字段映射、少量正常与退回例子；后续逐步补细节 | D1/D2/D5 的简版，允许先放在同一份文档中 | 同一份样表交给开发和关务，两方对任务、商品、编码和退回处理的理解一致；未决项明确 |
| 1 Excel 可靠进出 | 上传、解析、关联、查看、按规则插列导出 | 文件版本存储、解析器、图片关联、导出器、异常报告 | 更新 D2；D5 增加 Excel 对照结果 | 约定模板无静默丢行、串图或覆盖原列；公式、合并及图片等保留要求有样本证据；失败能定位 |
| 2 人工流程闭环 | 三角色完成提交、通过、两种退回和重传 | 工作台、角色权限、人工审核、问题分派、版本记录 | D3 接口与页面约定；更新 D1/D2/D5 | 不接 AI 也能走完正常与退回路径；服务端限制越权操作；提交绑定版本，旧版通过不沿用 |
| 3 接入 HS 预审 | 上传解析完成后自动启动，得到独立推荐、比较结论和补料问题 | 预审引擎、查询工具、结构化结果、任务进度与重试 | D4 Agent 输入输出与证据约定；预审评测记录 | 流程中的六类预审结论可复现；同码缺证据不会自动确认；查询失败单列；结果来源和输入可追溯 |
| 4 接入专家 AI 核查 | 专家看到要素、图片、退税和监管核查，再人工决定 | 专家核查引擎、证据展示、人工裁决及退回界面 | 扩充 D4；更新 D1/D3/D5 | 待审 HS 明确；未知和未核实信息显式展示；引用可定位；AI 不能自行通过或选定最终退回对象 |
| 5 版本变化与完整联调 | 新版补料后整表重审，旧版结果不被覆盖 | 版本对照展示、整表重跑、旧结果保护、完整导出 | 更新 D2/D3/D4；联调验收记录 | 旧版通过不沿用；旧任务回写、重复点击、并发版本不会串结果；对照对不上时有人工处理 |
| 6 业务试用与交接 | 业务方用真实脱敏案例从上传走到专家确认 | 可运行版本、验收记录、已知限制、部署与恢复说明 | D5 最终验收记录；D6 运行与交接说明 | 关键场景全部有记录，阻断问题清零；AI 质量经专家评估；负责人能按文档运行、恢复和定位失败 |

阶段 1 验证 Excel 进出能力，阶段 5 将真实审核结果完整回写到导出文件。补料重传首期按整表重审处理，行级影响判断和预审复用留作后续优化。

## 5. 开发任务清单

以下任务可直接转为开发事项。默认尚未开工；负责人、工期和排期在确认实际开发方式后填写。一个任务的边界以“输入明确、输出明确、可独立验收”为准，不强制按前端、后端分别切碎。

### 阶段 0：把基本规则说清楚

简单理解：正式写功能前，先拿现有模板把“系统认什么、谁决定什么、改了怎么办”约定清楚，减少后续返工。当前用户给出的任务粒度、待审 HS、商品行位置映射和模板范围，都属于这个阶段的成果。

起步只需三样：一页已确认/待定规则、一份标注字段及页签关系的真实脱敏模板、两三个正常或退回例子。D1/D2/D5 可先共用一份简版记录；字段类型、接口和完整测试用例在对应功能开发时逐步展开。

阶段 0 的业务规则、数据与模板映射、三个流程样例现已起草，统一从 [阶段 0 协作入口](阶段0/README.md) 阅读和批注。它们分别对应 D1/D2/D5 的初稿；真实工作簿核验和样例走查尚未完成。

输入：当前 HTML 流程、一份真实脱敏 Excel、关务人员的样例说明。

| 编号 | 开发准备任务 | 交付与验收 |
|---|---|---|
| 0.1 | 固定范围、角色与操作权限 | D1 明确供应商、业务员、专家各自能看什么、改什么、触发什么；记录本期终点。 |
| 0.2 | 对齐商品、版本、任务、结果和人工审批的含义 | D2 简版先明确一个文件一个审核任务、商品行按申报要素页签维度、模板字段及关系、关键 HS 阶段值和历史记录方案；字段类型等随开发补充。 |
| 0.3 | 建立样例及预期结果 | D5 覆盖正常、缺失、冲突、异常、退回、版本变化；AI 业务答案需专家标注。 |
| 0.4 | 确定实现与运行方式 | 记录首版运行方式、数据和文件保存位置、模型接入、查询来源可达性及角色认证方式。已有技术选型需按三角色协作和后台任务需求复核。 |

关口：能拿样表说明每个商品如何跨页签关联、图片属于谁、谁确认哪个 HS、退回后谁做下一步。真实模板未取得时可继续做界面草图，但阶段 1 的解析与保真验收保持待完成。

### 阶段 1：Excel 可靠进出

输入：D1/D2、约定模板、样例包。

| 编号 | 开发任务 | 交付与验收 |
|---|---|---|
| 1.1 | 实现上传、解析检查与原文件版本留存 | 上传后原文件可取回，解析状态明确；缺页签、打不开、缺关键列有定位；解析阶段本身不调用归类，自动预审在阶段 3 接入。 |
| 1.2 | 解析并关联装箱明细、申报行和附图 | 商品行以申报要素页签为主记录，装箱行作成员关联；保存主品名、别名、规格、型号及供应商原值；合同号＋项号存在歧义时提示处理，不任意匹配。 |
| 1.3 | 展示商品行及其文件定位 | 页面可逐行核对原值、页签、单元格和附图；读图失败单独提示，不能默认为“无图片”。 |
| 1.4 | 实现插列导出及保真核对 | 用明确标记的样例结果插入 AI 列；不覆盖右侧数据；对已声明支持的图片、公式和合并关系逐项核对。 |

交付证据：原始样表、解析出的预期数据、导出文件、逐项差异记录。发现复杂 Excel 特性无法保留时，先记录真实限制并解决范围问题，不把静默损坏作为可接受结果。

### 阶段 2：人工流程闭环

输入：阶段 1 的商品行和版本；D1/D2。专家使用业务员确认并提交的 HS。

| 编号 | 开发任务 | 交付与验收 |
|---|---|---|
| 2.1 | 建立三角色入口、列表与权限 | 供应商仅访问本人上传的审核任务，业务员管理所属审核任务，专家查看全部待审审核任务（首期仅一名专家、不分派）；直接请求接口也受权限限制。 |
| 2.2 | 实现业务员处置与提交快照 | 业务员选择待审 HS、查看问题、退回供应商或提交明确版本；导出独立于退回和发送。 |
| 2.3 | 实现专家人工审核与退回分派 | 人工通过或退回；专家可直接改码后通过，改码前后值与原因留痕；退回必须有对象、具体责任人、商品和原因，能分别退回业务员或供应商。 |
| 2.4 | 实现重传、版本对照与基本失效 | 新版不覆盖旧版，旧审批仍作为历史保留；新版本重新形成审核对象，禁止旧审批直接表示新版本通过。 |

可使用手工填写或明确标注的示例预审结果验证流程。示例结果不作为真实 AI 结论展示或验收。人工流程通过后，再验证模型效果，便于区分流程问题和 AI 问题。

### 阶段 3：HS 预审

输入：已校验的商品事实、当前版本、查询工具、D4 的预审部分。

| 编号 | 开发任务 | 交付与验收 |
|---|---|---|
| 3.1 | 定义预审输入与结果结构 | 商品事实与供应商 HS 分开；推荐阶段先使用商品事实和证据，再进入比较阶段；返回候选、原因、置信度、问题和来源状态。 |
| 3.2 | 实现证据查询与来源记录 | 查询记录文书标题、定位信息、链接、适用时间及查询时间；失败或未取得分别保存；历史和第三方信息作为线索。 |
| 3.3 | 实现自动触发、比较和页面展示 | 上传解析完成后自动创建预审执行，可手动重新预审；六类结论有清晰原因；原码与建议并列；同码但证据不足仍为无法确认。 |
| 3.4 | 实现任务进度、逐行失败重试和评测 | 单行失败不阻塞其他行；重试保留尝试记录；固定样本检查推荐、缺失项、置信度和引用。 |

进阶证据：输入版本、运行标识、结构化结果、来源记录、模型及规则版本、固定样本评测。页面完整不等于预审质量合格。

### 阶段 4：专家 AI 核查

输入：业务员提交快照、明确的待审 HS、商品事实和图片、有效预审结果、专家核查所需证据。业务员提交后自动触发专家 AI 核查。

| 编号 | 开发任务 | 交付与验收 |
|---|---|---|
| 4.1 | 按待审 HS 核查申报要素与图片可见事实 | 逐项展示供应商原值、AI 建议、匹配/冲突/未知及原因；不凭图片推断不可见工艺等事实。 |
| 4.2 | 接入退税与监管证据核查 | 按流程要求保存编码、日期、适用条件与来源；资料不足或来源不可达标为待核；与归类置信度分开。 |
| 4.3 | 展示专家核查结果和可定位依据 | AI 结论、专家置信度、补料清单与人工审批分开；无法取得法规时如实显示，禁止虚构条款。 |
| 4.4 | 将 AI 建议接入人工裁决界面并评测 | AI 可建议退回对象，专家确认最终对象及结论；专家可直接改码通过并留痕；高置信度也不自动通过；对正常、冲突和证据不足案例留存评测。 |

进阶证据：同一商品的预审结果和专家核查结果分别可查；专家能看到为什么待核、缺什么、证据在哪里。具体法规和税务规则的适用性由业务专家核验，本计划不作新的法律或税务结论。

### 阶段 5：版本变化与完整联调

输入：已跑通的两阶段审核、真实补料案例、D2 中的补料处理口径。

| 编号 | 开发任务 | 交付与验收 |
|---|---|---|
| 5.1 | 展示新旧版本对照并整表重跑 | 处理新增、删除、重排、拆分、合并和图片变化；按合同号、项号、型号和位置并排展示，对不上时人工处理；新版本整表重新预审。 |
| 5.2 | 保证旧结果不进入新版本 | 旧预审与旧审批只作历史；新版本重新预审、重新提交、重新专家审核；专家审核针对新提交快照记录。 |
| 5.3 | 防止旧任务和并发操作覆盖新数据 | 结果按版本、商品、任务写入；重复点击不产生重复提交；过期任务返回只存历史，不改当前审核状态。 |
| 5.4 | 输出完整结果文件和版本历史 | 预审列按要求相邻插入，原值、附图、公式和历史意见保留；专家确认值及问题清单可查；导出版本明确。 |

进阶证据：两种专家退回对象、供应商重传、归类相关变化、仅补证据、旧版已通过后再传新版、旧任务延迟返回，均有端到端记录。

### 阶段 6：业务试用与交接

输入：阶段 5 的完整版本、固定样本集、试用人员、D5/D6。

| 编号 | 开发任务 | 交付与验收 |
|---|---|---|
| 6.1 | 组织三角色完整验收 | 实际用户从上传到专家确认；记录操作、业务答案、系统结果、问题和复验，不只演示正常路径。 |
| 6.2 | 核验 AI 质量与支持范围 | 专家复核候选、关键补料问题、置信度、引用、退税与监管待核判断；公开样本范围和剩余限制。 |
| 6.3 | 完成部署、备份和恢复交接 | 按 D6 启动系统、恢复一份备份、定位一次失败任务；恢复内容覆盖数据库、上传文件、图片和审核历史。 |
| 6.4 | 关闭阻断项并形成试用结论 | 无未解决的数据损坏、越权、错误沿用审批、串版本、虚构依据或 AI 自动审批问题；其余限制有负责人及处理方式。 |

首版 AI 效果的总体准确率目标须在样本标注后与关务专家确定，不预设一个缺少依据的百分比。固定验收样本中的关键证据缺失误判为高置信度、虚构引用、监管待核项被无依据排除等问题，作为阻断项逐个修复；样本通过不表示全部商品均可靠。

## 6. 核心数据与状态的最小约定

以下供 D2/D4 细化，字段名是建议，不代表数据库已经建表。

| 对象 | 最少需要保留什么 |
|---|---|
| 审核任务 | 一个文件对应一个审核任务；保留审核任务标识、合同关联、供应商、业务员、专家、当前文件版本、汇总状态。补料重传在同一审核任务内追加版本（R07）。 |
| 文件版本 | 版本标识、原文件位置、上传人和时间、上一版本、解析状态、模板信息。 |
| 商品行及修订 | 稳定商品标识、当前版本修订、合同号/项号、主品名/别名、属性、原 HS/要素/退税率、图片定位；数据项来源与修改记录。 |
| 分析执行记录 | 所属审核任务、分析类型、输入版本/快照、商品范围、创建人、运行状态、重试记录、规则/模型版本。执行记录用于内部运行管理，不增加用户看到的审核任务数。 |
| 分析结果 | 任务与商品标识、候选、比较结论、置信度、事实、证据、缺口、来源状态。专家核查另含要素、退税和监管核查结果。 |

| 提交与人工审核记录 | 提交快照、待审 HS、引用的分析结果、人工确认编码及要素、退税/监管结论、通过/退回、审核人和时间。 |
| HS 修改日志 | 对应任务、商品行、文件版本、环节、修改前后值、操作者、时间和原因；AI 建议及采纳动作分别记录，不覆盖原值。 |

状态分开存，页面再组合展示：

- 业务阶段：待预审、业务员处理中、待专家审核、退回待处理、专家通过等。完整转换由 D1 明确。
- 任务运行：排队、运行、成功、部分失败、失败等；失败不代表商品有误。
- 预审比较：一致、不一致、无法确认、供应商未填、编码格式或有效性异常、关联异常。
- 证据来源：已取得、未取得、查询失败、版本待核等。
- 人工审批、预审置信度、专家置信度、监管状态：分别记录。

## 7. Agent 与业务系统如何衔接

Agent 读取版本化的商品事实、使用查询工具、形成结构化建议和补料问题。业务代码管理权限、文件版本、任务运行、状态变更及结果保存。业务员和专家执行提交、退回及通过。

Agent 输出应具备可校验的数据结构。网页和导出读取同一份保存结果，避免分别解析自由文本得到不同结论。独立推荐阶段的输入与供应商 HS 比较阶段分开，便于检查是否受到原码锚定。

需要记住的依赖：数据契约先于 Agent 接口，人工状态流转先于 AI 自动填充，Excel 保真样例先于批量导出承诺，版本绑定先于多角色正式使用。具体模型接入和框架可在阶段 0 确定，不据本计划提前锁定。

## 8. 固定验收场景清单

这些是 D5 的首批用例，预期业务答案待真实样本与专家核验；当前没有声称已执行通过。

| 编号 | 场景 | 必须检查的行为 |
|---|---|---|
| A01 | 供应商 HS 与 AI 一致且证据充分 | 可以形成一致的预审建议，仍需人工提交及专家确认。 |
| A02 | 同码但关键证据不足 | 输出无法确认和具体补料问题。 |
| A03 | 供应商 HS 与 AI 不一致 | 原码、建议及差异依据并列，明确待审值。 |
| A04 | 供应商未填 HS | 原字段保持未填，AI 建议单独保存。 |
| A05 | HS 格式异常或适用版本待核 | 区分格式、有效性及版本待核原因。 |
| A06 | 页签缺失、合同项重复或关联不清 | 定位文件/关联异常，不任意匹配。 |
| A07 | 图片无法读取或不属于当前商品 | 标明图片问题，阻止错误关联影响判断。 |
| A08 | 官方查询失败或未取得适用依据 | 来源状态单记，不评高，不虚构引用。 |
| A09 | 某行模型运行失败 | 其余行可继续，失败行单独重试。 |
| A10 | 业务员导出补料清单 | 无退回、发送或审批状态的隐式改变。 |
| A11 | 专家分别退回业务员和供应商 | 具体责任人、商品及问题均可追踪。 |
| A12 | 品名/规格/图片/HS 等归类输入变化 | 整表重新预审后重新提交专家，旧结论不沿用。 |
| A13 | 补充证据且确认不影响归类 | 首期仍整表重新预审；不引用旧预审，重新专家审核。 |
| A14 | 旧版本已通过，再上传新版 | 旧审批保留为历史，新版不直接通过。 |
| A15 | 旧任务延迟返回、重复点击或同时修改 | 不串版本、不覆盖新结果、不重复提交。 |
| A16 | 商品重新排序、增删或拆分 | 新旧对照可见、对不上有人工处理；整表重审；附图不串行。 |
| A17 | 导出包含图片、公式、合并及右侧原数据 | 与原样表对照，无静默损坏，新增列位置符合规则。 |
| A18 | 越权打开任务或提交审批 | 服务端拒绝未授权访问和动作。 |

每阶段验收都记录：版本/代码标识、执行人、样本、实际输出、结论和未解决问题。所有通过标准都应能拿出对应记录。

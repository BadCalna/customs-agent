# 实际业务模板与Skill适配说明

## 当前适配口径（2026-11-12）

以“业务员预审 → 专家审核”两阶段替代此前三表综合识别及自动回填方案；下方2026-11-10分析仅保留为历史文件观察，不作为本期执行指令。

1. 商品来源只看装箱明细、申报要素：合同第一条品名为主品名，附件清单品名为别名，规格与实际厂家/供应商型号联合使用，通过合同号＋项号定位附图。
2. 供应商上传不启动归类；业务员点击预审，AI独立推荐HS。原海关编码右侧依次插入AI推荐HScode、预审结论，保留供应商原码。差异/无法确认需写原因、置信度和待补资料；不覆盖原附图。
3. 专家审核逐项比供应商申报要素与图/规格，先处理编码分歧，再按适用税则、归类规则、税务退税政策及相关两用等法规解释。图片不能直接验证退税率。AI建议要素与原要素分开；原退税率不被推测值覆盖。
4. 业务员决定退回、导出补料或提交专家；专家明确退回角色/责任人与问题。预审/专家置信度、监管结论、人工状态分开；修改影响归类时重新预审。
5. 模板列位按表头：已经见到R为厂家型号或为合并申报的不同版本。插入两列后，原M附图及右侧要素/退税等相应移动，不能再固定L/M/Y等旧列回填。WPS图片、公式、合并及历史提示均须保真。

完整执行口径见 `skills/steel-hs-declaration/SKILL.md` 及 `references/business-template.md`；网页功能定义见 `网页端功能要点.md`。现有交互原型尚未实现本次两阶段交互。

## 2. 先建立商品与包装的对应关系

本表三个页签的有效数据范围如下；其他版本应按表头及数据边界重新定位，不将行号写死为通用规则。

| 页签 | 本表范围 | 实际粒度 | 用途 |
|---|---|---|---|
| 节点①箱件汇总 | 第9—31行 | 23行包装/箱组，合计45个包装件 | 尺寸、体积、包装数量与重量核对 |
| 节点①装箱明细 | 第5—68行 | 64行箱内商品分配记录 | 提取品名、规格、型号，关联箱号与合同商品 |
| 节点①申报要素 | 第2—48行 | 47个申报条目，部分合并多个合同项 | 读取已有填报、附图与审核历史，承接最终确认值 |

装箱明细中有6个合同、59个“合同号＋合同项号”组合。64行不能直接当成64种商品，也不能把47个已有申报条目当成全部原始商品。

- 包装关联：本次发运内，箱件汇总C列箱号 ↔ 装箱明细A列箱号。规范解析`M1-M4`、`M40-41`等箱组；保留原写法。序号不连续不直接认定少箱。
- 商品关联：本次上传/发运批次＋合同号＋合同项号，再以物料代码、规格和单位校验。合同项号按文本保存；同合同项出现不同规格或物料时保留子记录，待核实后处理。
- 申报关联：装箱明细B/E列 ↔ 申报要素B/C列。申报条目合并多个合同项时保存明确的成员列表，不依赖一个连字符字符串。
- 图片关联：申报要素M列附图先关联到该申报条目；条目包含多个规格时，不能默认一张图能够证明全部规格。
- 每条解析记录保留原文件版本、sheet、行号/单元格与内部记录ID。后续补料不能仅按当前行号更新，避免插行、排序造成错配。

## 4. Skill 输出如何进入实际模板

第一版建议导出原模板的审核工作副本，保留现有页签和记录，新增“AI核查明细”“三表校验结果”两个页签。业务页原有值与AI建议分开保存；人工确认后，才将确认值写入对应业务列。

| Skill输出/辅助能力 | 审核工作副本中的位置 | 确认后的业务落点 |
|---|---|---|
| 推荐HS、其他候选、归类理由 | AI核查明细 | 申报要素L列；多个候选不能拼入正式编码格 |
| 官方必填要素与已填/待补/冲突状态 | AI核查明细，逐要素保留值及来源 | 申报要素Y列，按最终编码适用模板和官方字段顺序生成 |
| 高/中/低及具体原因 | AI核查明细，置信度中黄、低红 | 作为审核依据，不自动变成审核状态 |
| 需补充或修改的信息 | AI核查明细，关联具体合同项和字段 | 生成供应商可逐项回答的补料清单 |
| 原品名、建议规范品名、最终确认品名 | AI核查明细，建议变化标黄并保留理由 | F列注明需与合同正文一致；与合同不一致的建议不能直接覆盖，由业务及物流确认文件一致性 |
| 名称是否替换 | AI核查明细最后一列 | 记录是否建议规范及是否已由人确认，不自动当成已替换 |
| 两用物项等监管线索 | AI核查明细，独立记录状态、依据、技术条件和待补资料 | 供物流复核；不通过改名称排除真实货物的管制属性 |
| 数据异常、来源链接、规则日期 | AI核查明细及三表校验结果 | 保留到商品和单元格，支持复查 |
| 英文品名建议 | AI核查明细，可作为轻量扩展 | 确认中文名称后生成E列；保留型号、数值和单位，不自行扩充技术性质 |

AI核查明细建议最小字段：记录ID、来源sheet/行、合同号、合同项号、物料代码、原品名、原HS、推荐HS、候选条件、归类理由、原申报要素、建议申报要素、缺失/冲突项、置信度、置信度原因、建议规范品名、最终确认品名、监管核查、来源与日期、人工处理状态、确认人及时间、名称是否替换。

不要借用N—P或Z—AA列：这些无表头列中已有实际审核意见。也不要把多个候选的要素混成唯一可提交的Y列文本。

其他字段分工：税分类代码D由财务/企业税务数据核实，不能把HS复制进去；退税率Q须有适用日期和业务条件的税务来源，不能只按HS或历史值自动决定；重量、尺寸等采用供应商实际资料并核对。

|---|---|---|

| 漏列申报条目 | M46减速机在装箱明细第68行，现有申报要素页未找到对应记录 | 提示是否属于本批申报范围；若属于，补建条目并执行识别，不能直接漏掉 |

## 6. 汇总、拆分与回填规则

1. 先按可追溯的合同商品记录判断，再决定是否合并申报。只因名称或HS相同不足以合并；还需核对适用申报要求、要素值、单位、产地、厂商等，并由业务/物流确认。
2. 同合同项分装多箱时，对齐规格等关键属性后复用归类判断，同时保留每箱数量/重量分配。硫化水胎32＋18＝50是本表可核对的案例。
3. 单价不同的原始合同项保留原价，不能被合并后的平均单价覆盖。合并金额按原行金额加总，展示单价按确认后的汇总规则计算；不得用四舍五入后的展示单价反推原始总额。
4. 包装数量和体积按实物包装统计一次。申报要素R/U有跨商品合并单元格，读取时保留关联组；不可向下填值后求和，也不可把这些空格一律报成缺失。
5. 净重、毛重按商品分配及包装总数分别核对，不把包装重量重复计入。尺寸统一单位后计算体积，识别合理的小数舍入差异；确认值与计算差异保留。
6. 不同计量单位的商品数量不能合成一个有业务意义的总数量。现有申报要素G49的13641混合了个、米、台、套等，不能据此判断总件数。
7. 归类置信度、申报要素完整度、装箱资料完整度、三表一致性、监管核查与人工审核状态分别记录。未装箱时缺尺寸重量不单独降低HS置信度，也不要求供应商猜填。

## 7. 轻量落地顺序

第一步：固定支持本次三页签模板，识别来源字段及行关系，生成三表校验报告；遇到重复键、异常合并项或缺页签，保留可处理部分并标出缺口。

第二步：调用现有Skill主流程，读取真实可用图片、查询适用日期的官方数据，输出建议、原因、置信度与补数；补充后仅重算受影响商品及关联汇总。

第三步：业务员定稿、物流确认，生成仍符合原模板布局的结果副本。合同后可先完成商品识别，实际装箱数据齐备后再做包装核对；物流审核后的下游动作仍待业务方补充。

模板回填由确定性的文件处理程序完成，并保留图片、公式、合并单元格、其他页签、原始字段及版本。该文件使用WPS内嵌图片，不能假定普通Excel库整本另存会完整保留；应选经过本文件验证的编辑方式，逐项核验图片引用和关系、公式/缓存处理、合并范围与写入位置，并检查目标WPS/Excel中的实际显示。

建议验收点：64行装箱记录全部可追溯；不重复分类分箱记录；47个原申报条目及其成员映射保留；减速机漏列、M15净重差异、品牌/功率矛盾能被提示；中黄低红和建议名称标黄正确；未确认的AI值不变成确认结果；导出后图片、公式、合并组和其他页签完整。

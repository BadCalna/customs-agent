# 两阶段模板字段与输出

只分析待审文件的装箱明细、申报要素两个页签；列字母为示例，不能当作跨文件固定位置。先查实际表头；新列插入后必须重新定位。历史成功表和映射底表是参考资料，不是待审文件的第三个业务页签。

## 随技能提供的两份参考表

- [兴大十部申报要素汇总_列修正_2026-11-17.xlsx](兴大十部申报要素汇总_列修正_2026-11-17.xlsx)：历史成功申报记录，`Sheet1` 的 E/L/M/AL 列分别为中文品名、HS编码、退税率、申报要素，C 列为19位税收分类代码。按品名、规格和要素事实找相近记录，再核对历史HS与退税率；不能只凭同名或历史成功认定本批商品及当前政策相同。
- [HS编码与申报要素及出口退税率映射_2026-11-17.xlsx](HS编码与申报要素及出口退税率映射_2026-11-17.xlsx)：`HS编码索引` 从第9行表头开始，A/B 为10位HS与商品名称，K 为出口退税率，L 为税务匹配编码，M 为匹配层级，N/O 为税率生效/失效日，P 为11位细分税码及税率，Q 为税率核验状态；`申报要素明细` 的 A/C/D/E 为10位HS、适用前缀、要素名称、必填标记。按10位HS精确查索引及对应明细，不能用前几位相似码代替完整码。索引第5至7行记录来源、版本与核对日期；使用时仍需核适用日期及官方更新。
- 历史表 C 列的19位税收分类代码与映射表 L/P 的8/10/11位退税商品代码不是同一编码体系，不能逐字符比较，也不能拿其中一个填另一个。若供应商另有退税商品代码，先识别其体系和位数；无可比字段时只比较其退税率并注明税码未提供。
- 申报要素原文可能以`|`或`｜`分隔，含顺序值、`字段：值`或两种混排。按映射字段顺序、名称和必填标记解析，保留原文与位置；不能只靠字符串包含判一致。必填项缺值标`缺失`，已有值与规格事实冲突标`冲突`；可选项未填不自动报错，无法证明真实性标`证据不足`。
- 钢材成分合计校验只加总同一申报行`成分含量`中明确给出的元素百分比，不把尺寸、牌号、退税率或其他字段中的百分数混入。保留原精度计算，不因四舍五入把99.9%写成100%；供应商明确注明“Fe余量”时记录其表述及已列数值合计，余量未经给出具体数值仍标待核。范围值、`<`/`>`或缺百分号且单位不明时不编造单一合计。

## 装箱明细：区分主品名、别名、规格和型号

| 语义字段 | 旧模板示例 | 使用规则 |
|---|---|---|
| 合同号＋合同项号 | B / E；另有模板为B / C | 与申报页定位商品，合并申报保存全部成员 |
| 合同第一条品名 | F；另有模板为E | 商品主品名；缺失明确标注，不由别名静默替换 |
| 附件清单品名 | G；部分模板没有 | 商品别名，用于检索消歧；冲突时同时保留，不改主名 |
| 规格 | H；另有模板为F | 提取真实尺寸、材质、功率、电压、用途等，保留原文 |
| 厂家提供型号／供应商提供型号 | 部分模板有独立列 | 与规格联合使用但分来源保存；型号列缺失就记缺列 |
| 物料代码、数量、单位 | 按表头 | 辅助关联；不能仅凭数量或商品名合并 |
| 生产商、产地、历史说明 | 按表头 | 明确资料可作佐证；生产商不直接推品牌 |

**已见模板差异**：某版本R表头为“厂家提供型号”，另两份实际测试表R为“合并申报”、S为“特别注意”，不能跨模板套列。只有规格中含型号时可提取，标为规格来源；适配设备型号与本体型号分开。用户本次口述“场景提供型号”暂按厂家/供应商提供型号处理，用途场景仍独立记录。

## 申报要素页：原值与AI结果并列

| 字段 | 原值或新增 | 阶段与用途 |
|---|---|---|
| 合同号、合同项号、品名 | 原值 | 两阶段关联核对，不按行号或同名跨合同匹配 |
| 海关编码 | 供应商原值，旧模板L | 比较对象，保留原文；空白为未填，不改成AI码 |
| AI推荐HScode | 新增/复用 | 业务员预审建议，**紧邻海关编码右侧** |
| 预审结论 | 新增/复用 | **紧邻AI推荐HScode右侧**；写比较状态、原因、预审置信度、补料要求和来源状态 |
| 附图 | 原值，旧模板M；可能无此列 | 有图才读取真实图片；无列/无图时按品名及规格型号预审 |
| 申报要素 | 供应商原值，旧模板Y或AD | 预审按AI推荐HS的映射要素逐项初核，专家复核；原值不被建议覆盖 |
| 退税率/退税商品代码 | 供应商原值，位置随模板变化 | 预审按AI推荐HS的映射税率/税码初核，专家核官方适用政策；区分19位税收分类代码 |
| 专家审核结论 | 新增/复用 | 逐项匹配结果、法规依据、适用条件、未决问题 |
| 建议申报要素 | 新增/复用 | 已证实值及红色待补占位，保留逐项来源；不替换原要素 |
| 置信度（专家审核） | 新增/已有置信度列 | 高/中/低＋依据＋补料；与预审置信度分别存储 |
| 退税率核查、监管核查 | 新增/核查明细 | 预审保留映射比较，专家补官方依据和监管条目/技术条件 |
| 退回对象、退回原因/补料清单 | 新增/审核记录 | AI可建议对象；最终由专家选择角色及责任人 |
| 人工审核状态、确认人/时间 | 新增/审核记录 | 与AI置信度分开；新版本不得继承旧版通过 |

目标连续顺序：`海关编码（供应商） → AI推荐HScode → 预审结论 → 原右侧字段`。例如旧L为海关编码、M为附图时，新增M/N后原附图右移至O；要素/退税列也可能改变，不能继续按旧字母回填。已有目标列放错位置时保留其内容并安全调整；合并跨列或图片锚点受影响必须验证，不能覆盖附图凑位置。

其他专家字段优先复用相应表头；缺失时追加到使用区之后，详细证据可放一个“AI核查明细”。无表头但已有“OK”“出口许可证”等的格不是空列，不得覆盖。已有“置信度”内混有许可证提示时先留存该提示，再写阶段明确的置信度。专家结果未运行时写“未执行/待专家审核”，不填虚假的通过或低置信度。

## 比较及补料输出

- 规范化仅处理确认为显示分隔符的空格/点等，保留原HS。校验是否完整10位、当期存在且适用；有效性待核不判定错误。
- HS同码示例：`一致｜供应商/AI：7306309000｜佐证：品名为焊接钢管，规格写外径114mm、壁厚4.8mm；映射商品描述为外径>10mm的圆形截面焊缝管，历史同类记录亦用此码｜退税率：供应商0%，映射0%，一致（8位回退匹配，待核当期适用）｜申报要素：逐项列匹配、缺失或冲突字段｜预审置信度：…`。此例只说明输出结构，不能套作其他商品结论。
- 同码但缺关键参数：`一致（HS码相同；归类待核）｜已有佐证：…｜缺口：…，尚不能证实细分条件｜退税率：…｜申报要素：…｜待补：…`；比较状态仍是`一致`，审核状态另行表达。
- HS异码示例：`不一致｜供应商：原码A；AI：建议B｜分歧：规格/用途表明…，A码适用条件为…，B码适用条件为…｜退税率：按B码核对…｜申报要素：按B码模板核对…｜待补：…`。A/B仅为格式占位，不是编码。
- 钢材成分示例：`一致｜申报要素有差异：成分含量C 0.2%、Mn 1.5%、Fe 97.8%，合计99.5%，距100%差0.5个百分点｜待补：核实各成分含量并提供完整配比`。示例仅说明披露格式，不作为该钢材的实际归类结论。
- 细分税码示例：映射`8543709990`的P列同时列出11位细分税码的9%和13%税率；未确定适用细分码时，即使供应商填13%、索引K列显示9%，也写`退税率待核`及需核的11位码，不直接判供应商错误。
- 缺供应商编码：`供应商未填｜AI建议：…或待补资料｜无法完成原码比较｜待补：供应商确认并填写HS及…`。
- 专家置信度：`低｜依据：原要素型号与本批铭牌不符，供货范围未明；退税适用代码及日期未确认｜待补/修改：本批铭牌、型号清单及税务依据`；具体条款和证据另见同商品专家结论。
- 系统不填写拟申报日期；需要适用日期时按查询日核查并标注“正式适用日期待核”，不要求补录该字段。
- 补料/退回记录至少含：商品ID及合同项、当前文件版本、问题字段、原值/证据、需补或修改内容、建议角色、人工选定角色/责任人、处理状态。导出与实际退回分开记录；未发送不写已通知。

## 网页与后端结果约定

按商品与版本保存两阶段结果；以下为开发建议字段，不表示已完成接口实现。

| 层 | 最小字段 |
|---|---|
| 商品及追溯 | `item_id`、`file_version`、`contract_no`、`contract_item_members`、`primary_name`、`alias_name`、`specification`、`supplier_model`、原单元格/图片引用 |
| 供应商输入 | `supplier_hs_code`、`supplier_elements`、`supplier_refund_rate`及原文；AI执行期间不变 |
| 预审 | `recommended_hs_code`、`candidate_conditions`、`hs_comparison_status`、`refund_comparison_status`（原率/映射率、税码体系、层级及日期）、`precheck_element_checks`（推荐码模板与供应商原值）、`precheck_conclusion`、`precheck_confidence`、`precheck_questions`、`precheck_sources`、`precheck_run_status` |
| 专家AI辅助 | `review_hs_code`（待审）及选择依据、`element_checks`、`image_checks`、`suggested_elements`、`refund_check`、`control_check`、`expert_conclusion`、`expert_confidence`、`expert_sources`、`expert_run_status` |
| 人工处置 | `business_decision`、`expert_decision`、`return_target_role`、`return_target_user`、`return_reasons`、`confirmed_hs_code`、确认值、确认人/时间 |

`precheck_confidence`和`expert_confidence`均为高/中/低；系统运行状态含未执行/执行中/成功/失败，失败不能伪装成低置信度或货物有误。来源包含发布机关、标题、条款/页码、URL、适用年度/生效日、查询日与适用商品事实。

规则或参考数据变更后，受影响结论标待复核并产生新运行版本。任何补料重传（含仅补要素/税务佐证）都整表重新预审，不区分未变商品，也不因只改要素列就认定不影响归类；业务员重新确认并提交后专家重新审核。已通过结果不可因复制文件或重传而自动沿用。
